# Roadmap

The reference document for the project is [`docs/vision.md`](docs/vision.md), which states what the project is, its invariants and its open questions. [`docs/architecture.md`](docs/architecture.md) is the map between the concepts and the implemented code — how the system works, from the top — updated when a checkpoint closes. This roadmap states the objective, the current state of the design, the checkpoints that mark progress from design to running system, and the framing rules that govern the work. The research reports are in [`docs/research/`](docs/research/).

## The project in one sentence

A **perpetual** system of LLM agents that follows a **direction** (not a finite objective) co-negotiated by chat between a human and an **agent zero**, whose structure **emerges** (nothing organizational is coded), on a minimal async event-driven kernel with an append-only frontier journal. Intended contribution (a survey-scoped hypothesis, not an established result): the triangle *perpetual × emergent × co-negotiated direction* appears unoccupied in the corpus surveyed here, with the measurement instrument that goes with it.

## Current state

Implementation phase. The design is settled and C1 is underway: the journal module (C1.1), the node driver (C1.2) and the durable context and provider boundary (C1.3) are implemented and tested. C1.3 delivers the context assembler and compaction (an incremental local-log fold, a provenance-bearing committed surface with a pinned heading and transactional compaction), the provider adapter (one canonical non-streaming wire), the bounded pinned world perception rendered from Git output, and disposable projection snapshots — with no snapshot-accelerated boot. **C1.4a delivers the kernel-mediated web tools** (`web_search`/`web_fetch`) over a kernel-side credential store (`<home>/providers.json`), dispatched through the same mutation gate as the shell; **C1.4b delivers the persistent terminal `execute`** — one PTY session per node, typed statuses, a bounded per-command capture and reset-on-timeout — **C1.4c delivers its Landlock filesystem confinement**: the shell runs by default through a vendored launcher, the world's git dir lives outside the worktree, and the content of `providers.json`, of the frontier journal, of the node's local log and of host files outside the explicit system read set is unreadable and unwritable from it; and **C1.4d delivers the frontier journal**: every kernel-mediated call (LLM provider and web tools) is journaled in `<home>/frontier/journal.v0.jsonl.zstd` — request durable before the send, terminal durable before the caller proceeds, `world_head` stamped on every request, boot-reconciled as `http/incomplete` — while the per-node journal is renamed `log.v0.*` and demoted to a cold-start artifact that observers never read, proven by an acceptance harness. The remaining plans follow the order in §10: **C1.4a, C1.4b, C1.4c and C1.4d are delivered**; the full placeholder↔endpoint broker remains the documented target; **C1.5** `extend`, **C1.6** agent zero + chat + `speak` and the disposable SQLite index and projections, **C1.7 — frontier completeness + escalating kill switch** (the reconstructability invariant is retired with C1.4d). C2 and C3 are **not** done — a checkpoint is reached when its criterion is demonstrated on a running system, not when modules bearing its name exist.

- **Kernel** ([`docs/kernel.md`](docs/kernel.md)). **The world is the filesystem**: the kernel imposes no message transport, nodes communicate by writing files, and the kernel commits the world at the end of every turn with the node's uid as git author — a node wakes on the commits it did not author, so a static world costs nothing, a dialogue is alternating commits, and a node's own commits never wake it. Event-native async runtime where every event — a world commit, a shell completion, an LLM response, a timer, a Package activation, a heading ratification — is an event and there is no blocking "waiting for the human" state. Free loop per node plus explicit wait, **unbounded** — self-excitation is observed, not prevented; the physical bounds are the upstream API ceiling, the kill switch, the frontier journal (and its gate), the mutation gate and the filesystem-confinement boundary. **Re-alignment** without interruption, so that propagation delay measures relaxation. A ratified heading is injected as a pinned reference into every node's context, while the flow-down of meaning travels through charters and delegation (emergent, observable). **Physical / behavioral frontier**: the kernel is the immutable physics (the frontier journal, the node's local log, mutation gate, kill switch, sandbox, budget ceiling); everything that makes a node's phenotype — loop, context and compaction policies, tools, instincts — ships as behavior Packages, introspectable and redefinable through `extend` (C1.5); the C1.3 context and compaction policies first arrive as trusted kernel-side behavior, not yet organism-replaceable. **Agent zero** is the root custody node, subject to the same physics. Stack: TypeScript / Node 24 LTS; `cordis@4.0.0-rc.10` (core only, gate wrapped, agent-written Packages in `node:vm` behind a restricted facade) is pinned when the checkpoint that uses it arrives (C1.5); rationale: the reference corpus is TypeScript, a reported study finds the large majority of compilation errors in LLM-generated code to be type errors (arXiv:2504.09246 — cited as a design rationale, not independently audited here), and transactional hot-reload has no comparable Python precedent. Journal: the **frontier journal** (one chain per cell home, `journal.v0.jsonl.zstd`) is the truth — canonical JSONL-zstd, RFC 8785 hash chain, claim-check for local payloads but never for frontier bodies (the blob holds the exact bytes, `complete: false` marks a bounded capture) — and the per-node `log.v0.*` is a cold-start artifact observers never read; deterministic replay of the local fold is free ("replay ≠ re-execution") — the disposable SQLite index keys the frontier stream and its projections arrive with agent zero (C1.6), which is what reads them. Cache-aware, byte-stable context assembler with one shared tool offer intended for all working nodes — a host/seed obligation, not an enforced invariant (the assembler hashes whichever config it is given, and each runtime takes its own initial config); capability mitigation stays at the gate, not at the offer; compaction by the dsh protocol with our own naive, visible policy. Sandbox: **the confinement is delivered** — **Landlock** (**C1.4c**; verified on the target machine: bubblewrap works here but remains unchosen, and Landlock ABI 8 works without root) confines the persistent `node-pty` PTY (**C1.4b**; does not survive a restart — accepted) behind a strict allowlist, making the API key physically unreadable from the agent's shell; the kernel-side credential store for the mediated web tools (**C1.4a**) is **implemented** (the full placeholder↔endpoint broker remains the documented target); the store is plaintext at rest but its content is unreadable and unwritable from the confined shell, while egress is left open by explicit decision for the experimentation phase. The world's git dir lives outside the worktree (`<home>/world.git`), so the shell has no path to the world history. The world is committed by the kernel at the end of every node turn, git author = the node's uid, commit hash recorded in `turn/end` — attribution is commit-granular, one shared working tree being able to carry a peer's in-flight writes, so the git layer says who moved the world when, not who wrote every line; per-file attribution is not recoverable today (per-node worktrees are the research direction), and the local log is a cold-start artifact and never an attribution source. The escalating kill switch with a 5-second non-tunable backstop is a **C1.7 target** that does not exist yet. Suggested construction order in §10 of the doc. **Honest status:** the hard physics the kernel relies on are the upstream budget ceiling on the API key, the escalating kill switch, the frontier journal (and its gate), the mutation gate and the filesystem-confinement boundary; the frontier, its gate and the confinement are delivered; frontier completeness and its proof (the acceptance harness) landed with C1.4d, so the escalating kill switch is C1.7's remaining build item and nothing is bounded by it yet. No overall completion percentage is claimed, and the project's place in the state of the art remains a design argument, not an established result. The **main host** — the daemon and cockpit that keep a perpetual node alive — explicitly arrives with C1.6 and owns process lifetime; the persistent PTY belongs to `execute` in C1.4b. Today the HEAD watcher deliberately keeps no process up (its interval is unref'd and an idle watcher holds no timer), so a process that runs a single parked node and nothing else exits silently by design.
- **Seed** ([`docs/seed.md`](docs/seed.md)). The kernel knows only the recursion of Γ — a single **node** primitive of self-similar shape, with custody and authority as two distinct graphs (the leak test: an organizational projection isomorphic to the custody tree on every run is a design failure). The seed is a strict subset of the means the heading requires, leaving a calculated **Hole** (naive, visible compaction; no memory management provided) that the agents must outgrow. Its content: 5 instincts (Name, Keep, Tool up, Ask, Signal) as dispositions, never products, each with a known counterfeit; Finitude reduced to the Hole alone, with the budget invisible to the agent and enforced as a hard limit upstream on the API key; **raw tools** — `speak`, `execute` (the persistent PTY session), `web_search`/`web_fetch`, `extend` (the single Cordis gate) — with no business-shaped tooling; no approval guardrail and no provided memory, so that free evolution is observed and the agent, made self-aware of its machine, builds its own context management; a provisional, expiring direction v0 that is destined to die at the first negotiation; `spawn` held in the kernel, not mounted, discoverable by introspection through `extend → inspect`. Three falsification instruments, invisible to the agents and computed from the frontier journal + the world: genesis adjacency rate, org/runtime isomorphism, organ usage graph. `Emergence = Necessity × Propensity` is the ablation-testable hypothesis; the reported finding that minimal scaffolding outperforms full autonomy (Dochkina) is cited as an uncertain external reference pending audit, and its specific figures live in the research corpus rather than as a settled quantitative claim here.
- **Direction** ([`docs/direction.md`](docs/direction.md)). Three physical roles, never mixed: the human (source), **agent zero** (translator co-orchestrator, intention ↔ heading in both directions; it does not work, and it reads raw facts, never the metrics — the anti-Goodhart line), and standard nodes (never any direct human contact). `speak` walks up the custody chain, so the human channel belongs to agent zero alone. The direction is a **double artifact**: the pinned verbatim **heading** carrying the cycle's **value proxy** (visible to the agents — it is their work target), plus the versioned rich **letter** readable on demand. Agent zero drafts, the human ratifies; the dated ratification event is the single ground truth of the metrology (its home is a C1.6 design point — a local/world fact, never a frontier fact). Cadence is free, with a recorded recommendation of rare headings, since headings too close together make relaxation unmeasurable. Pinning outside compaction answers Governance Decay (arXiv:2606.22528) — a reported, not independently audited, result that compaction erodes constraints while pinning restores them; its specific figures are held as an uncertain reference pending reconciliation in the research corpus, not restated as a quantitative claim here. A rich direction is not pinnable as is, which is what forces the double artifact. Sycophancy is not instrumented at this stage.
- **Monitoring instrument** ([`docs/vision.md`](docs/vision.md) §3–5, [`docs/research/`](docs/research/)). Monitoring precedes all software design: the instrument defines the apparatus. Settled form: **3 sensors + 1 metronome** — semantic trajectory via embeddings (phase, temporal novelty, diversity, drift), structure graph (RSI, hierarchical coherence, turnover, March cascade), value registry (promises → acts → effects, with a value proxy negotiated per cycle); the metronome is the versioned direction, which labels adaptation against drift. Novelty is temporal — an unseen action, or an old action in a changed world (org + direction + knowledge). Exploration/exploitation is read by embeddings rather than dictionaries (Uotila 2009 abandoned as too fragile; precedents SemNovel 2025, arXiv:2601.17617), and embeddings measure movement, not intention, so cross-checking against the versioned direction is mandatory. The catalogue of ~20 metrics becomes a diagnostic manual — a posteriori queries recomputable from the frontier journal + the world. The observation surface and the analysis pipeline behind these readings — observation physically outside the world, three deterministic layers (tree-sitter code graph, social/prose parser, git layer) and the EXTRACTED/INFERRED honesty model — are specified in [`docs/research/monitoring-architecture.md`](docs/research/monitoring-architecture.md). References: Uotila 2009; Lehman & Stanley; March 1991; Scheffer 2009; arXiv:2603.28990; arXiv:2505.02709; arXiv:2606.22528; ITS/CausalImpact; [`docs/research/devils-advocate.md`](docs/research/devils-advocate.md), [`docs/research/value-adaptation-coupling.md`](docs/research/value-adaptation-coupling.md), [`docs/research/value-measurement-long-horizon.md`](docs/research/value-measurement-long-horizon.md), [`docs/research/exploration-exploitation-metrics.md`](docs/research/exploration-exploitation-metrics.md). Feasibility: the metrics exist individually and the unified instrument appears unoccupied in the surveyed corpus — that framing is the hypothesis of the contribution, not a demonstrated result; the theorems constrain optimization, not observation, and the self-evolution trilemma (Wang 2026) establishes external human steering as necessary — the concept of the project. Two memories are kept distinct: the **frontier journal + the world** (layer 1 — the physical trace wired at the level of the LLM API calls, immutable; the node's local log is a cold-start artifact, not part of it) and the agents' emergent useful memory, untouched (layer 3), whose usage remains visible in the trace. No hardware constraint: model choice is a cost lever, and the cache hit rate is the first one (candidates in [`docs/research/models-overview.md`](docs/research/models-overview.md)).
- **Scope.** P4 (autonomy must be earned) and P5 (never live) are outside the kernel: operating live *is* the concept, and any right agent zero needs is asked for in the chat — the asking is experiment data, not a specification. No rights, authorization or promotion system exists.

## Checkpoints

A checkpoint is reached when its criterion is demonstrated on a running system, not when its parts are coded.

- **C1 — minimal kernel + agent zero + chat + a readable projection of the frontier journal.** *Criterion: we can see everything the agent does, and we can talk to it.*
- **C2 — agent zero hot-extends the system on its own initiative** (it installs a module, the module persists, the system survives a restart). *Criterion: reversibility demonstrated — clean unload.*
- **C3 — `spawn` + direction.** *Criterion: at comparable budget per unit of time, the organization maintains a coherent trajectory where a solo agent drifts or collapses.*

## Framing rules

- **No code before the design is validated.** A component is designed (brainstorm → spec → plan) before it is implemented.
- **Golden rules.** No organizational structure is coded. Metrics are invisible to the agents (anti-Goodhart), and fidelity is measured on acts, never on declarations. The frontier journal is the only truth — dashboards, metrics, agent memory and the node's local log are disposable projections or cold-start artifacts. Replay is not re-execution.
- **Hard physics.** Kill switch, upstream budget ceiling, the frontier journal (and its gate), the mutation gate, and the filesystem-confinement boundary — the confinement boundary is a kept physical bound, like the gates: it constrains where agent effects can land, not what the kernel records. Nothing else is kept: everything else is stated in the direction and observed in the frontier journal + the world.
- **Roles.** The human supplies intuition and vision. The implementation partner verifies feasibility, sources evidence, challenges, and records.
- **Versioning.** Everything is in git; the commit history is the project's chronicle for the future paper.
