# Roadmap

The reference document for the project is [`docs/vision.md`](docs/vision.md), which states what the project is, its invariants and its open questions. This roadmap states the objective, the current state of the design, the checkpoints that mark progress from design to running system, and the framing rules that govern the work. The research reports are in [`docs/research/`](docs/research/).

## The project in one sentence

A **perpetual** system of LLM agents that follows a **direction** (not a finite objective) co-negotiated by chat between a human and an **agent zero**, whose structure **emerges** (nothing organizational is coded), on a minimal async event-driven kernel with an append-only journal. Intended contribution: the unoccupied triangle *perpetual × emergent × co-negotiated direction*, with the measurement instrument that goes with it.

## Current state

Implementation phase. The design is settled and C1 is underway: the journal (C1.1) and the node driver (C1.2) are implemented and tested; the remaining plans follow the order in [`docs/kernel.md`](docs/kernel.md) §10.

- **Kernel** ([`docs/kernel.md`](docs/kernel.md)). Event-native async runtime where every event — human message, shell completion, LLM response, timer, Package activation, heading ratification — is an event and there is no blocking "waiting for the human" state. Free loop per node plus explicit wait, **unbounded** — self-excitation is observed, not prevented; the only physical bounds are the upstream API ceiling and the kill switch. **Re-alignment** without interruption, so that propagation delay measures relaxation. A ratified heading is injected as a pinned reference into every node's context, while the flow-down of meaning travels through charters and delegation (emergent, observable). **Physical / behavioral frontier**: the kernel is the immutable physics (journal, mutation gate, kill switch, sandbox, budget ceiling); everything that makes a node's phenotype — loop, context and compaction policies, tools, instincts — ships as behavior Packages, introspectable and redefinable through `extend`. **Agent zero** is the root custody node, subject to the same physics. Stack: TypeScript / Node 24 LTS; `cordis@4.0.0-rc.10` (core only, gate wrapped, agent-written Packages in `node:vm` behind a restricted facade) is pinned when the checkpoints that use it arrive (C1.4-C1.5); rationale: the reference corpus is TypeScript, 94% of compilation errors in LLM-generated code are type errors (arXiv:2504.09246), and transactional hot-reload has no comparable Python precedent. Journal: canonical per-node JSONL-zstd, RFC 8785 hash chain, claim-check beyond a format-constant threshold, deterministic replay for free ("replay ≠ re-execution") — the disposable SQLite index and its projections arrive with agent zero (C1.6), which is what reads them. Cache-aware, byte-stable context assembler with an identical tool offer for all working nodes (mitigation at the gate, not at the offer); compaction by the dsh protocol with our own naive, visible policy. Sandbox: **Landlock** (verified on the target machine: bubblewrap broken by default, Landlock ABI 8 functional without root), making the API key physically unreadable from the agent's shell; persistent `node-pty` PTY (does not survive a restart — accepted); git commit driven by the kernel on return from each `execute`. Escalating kill switch with a 5-second non-tunable backstop. Suggested construction order in §10 of the doc.
- **Seed** ([`docs/seed.md`](docs/seed.md)). The kernel knows only the recursion of Γ — a single **node** primitive of self-similar shape, with custody and authority as two distinct graphs (the leak test: an organizational projection isomorphic to the custody tree on every run is a design failure). The seed is a strict subset of the means the heading requires, leaving a calculated **Hole** (naive, visible compaction; no memory management provided) that the agents must outgrow. Its content: 5 instincts (Name, Keep, Tool up, Ask, Signal) as dispositions, never products, each with a known counterfeit; Finitude reduced to the Hole alone, with the budget invisible to the agent and enforced as a hard limit upstream on the API key; **raw tools** — `speak`, `execute`, `web_search`/`web_fetch`, `extend` (the single Cordis gate) — with no business-shaped tooling; no approval guardrail and no provided memory, so that free evolution is observed and the agent, made self-aware of its machine, builds its own context management; a provisional, expiring direction v0 that is destined to die at the first negotiation; `spawn` held in the kernel, not mounted, discoverable by introspection through `extend → inspect`. Three falsification instruments, invisible to the agents and computed from the journal: genesis adjacency rate, org/runtime isomorphism, organ usage graph. `Emergence = Necessity × Propensity` is the ablation-testable hypothesis (Dochkina: minimal scaffolding beats full autonomy by +44%, d = 1.86).
- **Direction** ([`docs/direction.md`](docs/direction.md)). Three physical roles, never mixed: the human (source), **agent zero** (translator co-orchestrator, intention ↔ heading in both directions; it does not work, and it reads raw facts, never the metrics — the anti-Goodhart line), and standard nodes (never any direct human contact). `speak` walks up the custody chain, so the human channel belongs to agent zero alone. The direction is a **double artifact**: the pinned verbatim **heading** carrying the cycle's **value proxy** (visible to the agents — it is their work target), plus the versioned rich **letter** readable on demand. Agent zero drafts, the human ratifies; the dated ratification event is the single ground truth of the metrology. Cadence is free, with a recorded recommendation of rare headings, since headings too close together make relaxation unmeasurable. Pinning outside compaction answers Governance Decay (0% → 30–59% violation after compaction; pinning → 0%, arXiv:2606.22528); a rich direction is not pinnable as is, which is what forces the double artifact. Sycophancy is not instrumented at this stage.
- **Monitoring instrument** ([`docs/vision.md`](docs/vision.md) §3–5, [`docs/research/`](docs/research/)). Monitoring precedes all software design: the instrument defines the apparatus. Settled form: **3 sensors + 1 metronome** — semantic trajectory via embeddings (phase, temporal novelty, diversity, drift), structure graph (RSI, hierarchical coherence, turnover, March cascade), value registry (promises → acts → effects, with a value proxy negotiated per cycle); the metronome is the versioned direction, which labels adaptation against drift. Novelty is temporal — an unseen action, or an old action in a changed world (org + direction + knowledge). Exploration/exploitation is read by embeddings rather than dictionaries (Uotila 2009 abandoned as too fragile; precedents SemNovel 2025, arXiv:2601.17617), and embeddings measure movement, not intention, so cross-checking against the versioned direction is mandatory. The catalogue of ~20 metrics becomes a diagnostic manual — a posteriori queries recomputable from the journal. References: Uotila 2009; Lehman & Stanley; March 1991; Scheffer 2009; arXiv:2603.28990; arXiv:2505.02709; arXiv:2606.22528; ITS/CausalImpact; [`docs/research/devils-advocate.md`](docs/research/devils-advocate.md), [`docs/research/value-adaptation-coupling.md`](docs/research/value-adaptation-coupling.md), [`docs/research/value-measurement-long-horizon.md`](docs/research/value-measurement-long-horizon.md), [`docs/research/exploration-exploitation-metrics.md`](docs/research/exploration-exploitation-metrics.md). Feasibility: the metrics exist individually and the unified instrument is virgin territory, which is the contribution; the theorems constrain optimization, not observation, and the self-evolution trilemma (Wang 2026) establishes external human steering as necessary — the concept of the project. Two memories are kept distinct: the **journal** (physical trace wired at the level of the LLM API calls, immutable, layer 1) and the agents' emergent useful memory, untouched (layer 3), whose usage remains visible in the trace. No hardware constraint: model choice is a cost lever, and the cache hit rate is the first one (candidates in [`docs/research/models-overview.md`](docs/research/models-overview.md)).
- **Scope.** P4 (autonomy must be earned) and P5 (never live) are outside the kernel: operating live *is* the concept, and any right agent zero needs is asked for in the chat — the asking is experiment data, not a specification. No rights, authorization or promotion system exists.

## Checkpoints

A checkpoint is reached when its criterion is demonstrated on a running system, not when its parts are coded.

- **C1 — minimal kernel + agent zero + chat + a readable projection of the journal.** *Criterion: we can see everything the agent does, and we can talk to it.*
- **C2 — agent zero hot-extends the system on its own initiative** (it installs a module, the module persists, the system survives a restart). *Criterion: reversibility demonstrated — clean unload.*
- **C3 — `spawn` + direction.** *Criterion: at comparable budget per unit of time, the organization maintains a coherent trajectory where a solo agent drifts or collapses.*

## Next step

The implementation of **C1** — minimal kernel, agent zero, chat, readable projection of the journal — follows the construction order suggested in [`docs/kernel.md`](docs/kernel.md) §10 (journal and hash chain first; then the node driver; then the assembler, provider adapter and pinning; then `execute`, `speak`, `web_search`/`web_fetch`; then `extend`; then agent zero; then the reconstructability invariant and kill switch), as a sequence of seven plans: **C1.1** journal, **C1.2** node driver, **C1.3** assembler + provider adapter + pinning, **C1.4** tools, **C1.5** `extend`, **C1.6** agent zero + chat, **C1.7** invariants. The plans live in [`docs/plans/`](docs/plans/).

Then the monitoring/cockpit session: the readable projections carrying the 3 sensors and the metronome, and the smallest cockpit interface that shows the trajectory. The **cockpit** is a navigation instrument, not a debug tool. Its cost and its readings are journaled like any other intervention.

## Framing rules

- **No code before the design is validated.** A component is designed (brainstorm → spec → plan) before it is implemented.
- **Golden rules.** No organizational structure is coded. Metrics are invisible to the agents (anti-Goodhart), and fidelity is measured on acts, never on declarations. The journal is the only truth — dashboards, metrics and agent memory are disposable projections. Replay is not re-execution.
- **Hard physics.** Kill switch, upstream budget ceiling, journal. Nothing else is kept: everything else is stated in the direction and observed in the journal.
- **Roles.** The human supplies intuition and vision. The implementation partner verifies feasibility, sources evidence, challenges, and records.
- **Versioning.** Everything is in git; the commit history is the project's chronicle for the future paper.
