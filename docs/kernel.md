# Kernel — technical specification

The runtime's specification: the two records, the world and node driver, the context assembler, the sandbox, the credential store, and the target designs owned here. Concepts: [vision.md](vision.md), [seed.md](seed.md), [direction.md](direction.md). Progress: [ROADMAP.md](../ROADMAP.md). Concepts→code: [architecture.md](architecture.md). Status vocabulary: **implemented** / **specified, not implemented** / **rejected**.

## Runtime behavior

- **Async, event-native, non-blocking.** No "waiting for the human" state: a node raises a problem by writing in the world or by sending it to the gateway on the conversation interface, and the answer arrives as a change it wakes on (a foreign commit, or a conversation notice). dsh's `ask_user_question` blocks a turn on the human — the rejected counter-model.
- **Free loop, explicit wait, physical time.** No cap on change-triggered wakes (dsh's `maxConsecutiveWakes` — rejected: observation over prevention); a proactive timer wake carries a bounded sliding-hour budget, so self-initiated cost is bounded without ever suppressing the observation of a change. Physical bounds: upstream budget ceiling, kill switch, frontier journal and its gate, mutation gate, confinement boundary.
- **Re-alignment without interruption.** A ratified heading propagates to every node's next turn as a verbatim pinned reference; the propagation delay is the relaxation measure (`direction.md` §2–§3); flow-down travels through charters and delegation.
- **Mechanism and policy.** The kernel is the physics (the two records and their gates, watcher, commit-per-turn, sandbox); loop, context and compaction policies are phenotype — trusted kernel-side behavior; `extend` (**implemented**) delivers mechanism and tool Packages, and the policy-replacement seam stays **specified, not implemented** (a policy Package arrives through the same facade, never in-kernel trust, when C2 demonstrates the need). Policy changes are local-log facts; the frontier records HTTP exchanges only. **Agent zero is the gateway — an overlay, not a node.** It is a host-side, single-tenant digest service living over the system, and it is not in the NodePool: no cell, no cgroup leaf, no scratch, no local log, no Landlock sandbox, no world grant, no turn-end commit, none of the node verbs. Its equipment is kernel — the event-driven cycle (`src/overlay/`), the two watchers, and its three tools (`send_message`, `read_world`, `world_log`) — and its role is charter data (`<home>/gateway.charter.md`, supplied by `--gateway-charter`). One cycle per coalesced arrival from either surface digests both bounded windows; a successful cycle delivers exactly one chat record, its final prose; the overlay has no speak tool and no world-write capability of any kind. A start without `--gateway-charter` is nodes-only even when a persisted pair exists; a `resume` takes the persisted pair. The conversation interface (`send_message`/`get_messages` over the kernel-owned stream), the world-ratified direction pin and the human's `direct` write acts (the batch chat reply and the `--path` ratification) are implemented, while the versioned proposal (heading + proxy + letter) and raw-frontier reading remain specified, not implemented; proposing plain heading text in a chat response is the implemented convention (`direction.md` §1, the gateway charter template).

## Stack

TypeScript strict mode (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`), Node 24, Vitest; exactly two runtime dependencies (`AGENTS.md`). The Cordis pattern (Plugin→Packages→Runs, LIFO-trivial — one live Run, arXiv:2608.25512 Theorem 16) is implemented natively (content-addressed Packages persisted under `nodes/<uid>/packages/`, Runs as confined children with strictly sequential disposal); the library itself is **rejected** as a dependency (pre-release, single-maintainer, an open lifecycle race, concurrent-disposal composition weaker than the theorem's provable order). `@cordisjs/plugin-loader`/HMR: **rejected** (documented races and loader hangs, cordis #194/#154; Node internals + native addon). Design basis: on average 94% of compilation errors in LLM-generated TypeScript are type errors (arXiv:2504.09246, the paper's own measurement) — the invariants here are what a type system makes unavoidable; the reference corpus (Cordis, dsh) is TS; 0/11 production harnesses import an agentic framework in the agent runtime (arXiv:2609.00006, Observation 13.2, static-analysis caveat); SWE-PolyBench (arXiv:2504.08703) is the repo-level reference. Fallback: Python 3.14 + anyio, hot-reload = clean shutdown + remount, never `importlib.reload` (python.org: extension modules "may fail in arbitrary ways" on reload; no transactional hot-reload precedent found in Python).

## Cell-home layout

```
cell-home/
├── world/                      # the worktree — the only node↔node communication channel
├── world.git/                  # the world's git dir, kernel-owned, outside the worktree
├── tmp/<uid>/                  # per-node shell scratch leaf (0700, kernel-created)
├── frontier/
│   ├── journal.v0.jsonl.zstd   # THE TRUTH — append-only, hash-chained, one total order
│   ├── journal.v0.head         # chain checkpoint {first_hash, last_hash, count, ts}
│   ├── journal.v0.lock         # flock sidecar (stable inode)
│   ├── journal.v0.owner        # durable owner record {pid, startedAt, token}
│   └── attribution.v0.jsonl    # {v, call, uid} per begun exchange — the actor beside the node-blind chain
├── nodes/<uid>/
│   ├── log.v0.jsonl.zstd       # the node's cold-start log — no outside observer reads it (the node's own reading is its act)
│   ├── log.v0.head / .lock / .owner
│   ├── snapshots/<seq>.json    # projection checkpoints (disposable, retention 2) — specified, not implemented; no host wires the hook
│   ├── packages/<sha256>/     # durable Package definitions (package.js, manifest.json)
│   └── runs/<runId>/          # transient Run leaves — reaped at boot, never survive a restart
├── .es/                        # world flock sidecar (world.lock), the conversation and chat flocks (conversation.lock, chat.lock) + quarantine/ (moved-aside untracked paths, 0700)
├── providers.json              # kernel-side credential store — plaintext at rest
├── world-state.json            # degraded-world projection (written at refusal, 0600); not a record
├── conversation.v0.jsonl       # the conversation stream — the interface (0600, append-only); one {v, at, from, to, text} record per line
├── chat.v0.jsonl               # the human channel's chat log (0600, append-only); the human↔overlay surface
├── gateway.charter.md          # the gateway overlay's charter (0600, atomic) — the overlay's role
├── gateway.json                # the gateway overlay's model (0600, atomic) — {v, model}; the config pair is the resume's source
├── blobs/<2 hex>/<sha256>      # content-addressed store, shared by both layouts
└── index.sqlite                # disposable index — specified, not implemented
```

The frontier journal is the truth: one chain per cell home, every kernel-mediated HTTP exchange durable before the effect, no knowledge of nodes, turns or Packages. The node's local log is its cold-start artifact; no outside observer reads it, and the instrument does not take its timeline from it. The node's own `history` read is the node's act — an ordinary `tool/call` + `tool/result` in the local log — not an observation surface and not a truth upgrade. The world's git history is the second observation surface. They join through both halves: every `http/request` carries the kernel-stamped, best-effort `world_head` (`null` when unreadable — an exchange on the world's timeline; the attribution sidecar, not the field, names the node); every `turn/end` that closed a successful commit carries that turn's commit hash (commit-granular, at recorded turn boundaries) — a refused or empty turn's closer carries none.

**Multi-node host.** One host runs N nodes on one home (`--nodes-file`, at most 16 entries): one world repo, one world-doctor pass, one frontier journal and its attribution sidecar, and one storage seam, shared; one runtime, driver, local log, scratch leaf and cgroup leaf per node. Every mediator each node owns receives its own attribution view, so each exchange is attributed to its node. Turns may run concurrently; commits serialize on the world's existing per-path queue and the fence freezes every `node-*` and `run-*` leaf. The owner record carries the first node's uid (liveness metadata, not a per-node fact) and `host/boot` is emitted once per node. A solo boot (no `--nodes-file`) composes exactly one node, unchanged; the nodes file is read and validated at the config gate (a malformed file is exit 2 and writes no owner record), and each node's config is journaled by the ordinary per-uid gate.

**Ratified direction.** The pinned heading is the world's direction, not a static boot value: at each turn boundary the kernel reads `DIRECTION.md` at the latest commit authored by the reserved human ratifier (`human` is never a node uid, so no node can commit a ratification) and pins its content — at most 8 KiB with a truncation notice — as the heading block, citing the ignorable local fact `direction/pinned {commit, bytes}`. A node's own commit of the file is a draft: it is in the world's history, which is the archive, but it is not authoritative until the human ratifies it. The human's act has a command: `direct --path DIRECTION.md --file <abs>` (`src/node/world-ratify.ts`) validates the file, hashes its bytes through git stdin, builds the commit from a fresh private index seeded at the current HEAD (a root commit on an unborn branch), authors it with both identity pairs as the reserved `human`, moves the branch with a compare-and-swap, and materializes the worktree copy — so the pin moves at every node's next turn boundary, and no node-authored commit can move it. The act's git children contend with the nodes' turn-end commits: a held world lock is a typed refusal, retried on both sides within the kernel's bounded discipline, so a ratification and a turn-end commit may each briefly refuse the other. No ratified direction, an empty one, or an unreadable world read (one bounded `DirectionUnavailableError` diagnostic) pins the journaled seed heading instead; the read is two bounded git reads per turn.

**The human channel.** The node offering carries no `speak` verb: the human channel's surface is the overlay's native chat — the human's typed records and the overlay cycle's response records in `<home>/chat.v0.jsonl` (0600, append-only, kernel-owned, outside the world; the human has no file to read; a torn tail is dropped at open). The cycle's side is **implemented**: each successful cycle appends exactly one `uid: gateway` record (its final non-empty assistant text, capped at 8192 bytes; the kernel's bounded no-reply notice when the cycle ended with no prose), and the `ChatWatcher` — actor-filtered on `uid: human` growth — is the second trigger. The human's own writing surface is the interactive `chat` session, **implemented**: `chat --home <dir>` renders the recent chat log (both sides' records interleaved, ISO-8601 UTC, `--tail N`) and then runs the prompt loop — a typed non-blank line (≤ 8192 bytes) is appended as one `{v: 0, at, uid: human, text}` record through the `ChatWriter` under `<home>/.es/chat.lock`, the `ChatWatcher` triggers the overlay's cycle, the new `uid: gateway` record renders and the prompt returns. The wait is bounded (60 s, a "still waiting…" note at intervals): on timeout the message stays saved and the overlay's next cycle digests it; Ctrl-C aborts the wait, not the session; an absent `gateway.charter.md` is detected up front and the message is saved for when the overlay is configured (the presence check's residual: a configured-but-stopped host passes it and the timeout is the backstop). EOF/Ctrl-D exits 0; a degraded history exits 1. The chat log has THREE cross-process writers — the cycle, the session and `direct` — under the one `.es/chat.lock` with the shared termination-first append (`src/locked-append.ts`); the boot repair stays host-only. `--conversation` renders the raw conversation stream read-only beside the chat, re-read and re-rendered before each prompt within the open render's `--tail` bounds (so a relay arriving mid-session is visible without a restart); `--json` prints the chat records and exits; a non-TTY stdin renders the history and exits, so a scripted `chat` never hangs. The batch twin is `direct`, **implemented**: `direct --home <dir> (--text | --file)` (`src/host/direct.ts`) appends the same `{v:0, at, uid:human, text}` record through the same `ChatWriter` under the same lock, returns without waiting (the `ChatWatcher` triggers the cycle cross-process), and makes NO world commit — the human's words stay chat-private. `direct --path <world-relative> --file <abs>` is the ratification, the one world-writing act outside a turn (the `Ratified direction` paragraph). The chat log's record shape is unchanged (`{v, at, uid, text}`), its `uid` follows the conversation actor rule, and no node verb writes it. Saying the successor is native means what it says: the overlay converses in its own cycle's prose, never through a tool call.

**The two-zone trust model.** The conversation and the chat log are kernel-owned end to end: the home's kernel-owned files are outside every shell's grant — inside the home the shell reaches only the world and its own per-node scratch leaf `<home>/tmp/<uid>` — so no node can read, write, plant, forge or truncate either file; through the sanctioned tools a participant reads only its own thread (the filter is the kernel's), and every sender is kernel-stamped, so attribution is honest by construction. The far west — the world — is public, unauthenticated and vandalizable by any node that can write it: whatever it holds is data, not authority. The overlay's asymmetry is the other half: the gateway has no world access of its own (its reads are kernel-mediated `read_world`/`world_log` calls, each riding a frontier exchange), it holds no world-write capability by construction, its answers to the human live in the kernel-honest chat log and its sends in the conversation, and the world contains nothing authored by the gateway because it has no way to author it. The human's audit path for the world is the world's git; the corrective for the recap is the raw conversation stream beside it in `chat`.

**Interface residuals.** (i) The overlay is the interface's single drain point: every question funnels through its recap — cheaper than world-broadcast turns, but a busy society outpaces one reader; the lag is human-visible in `chat` (the raw stream, rendered with `--conversation`, grows while the recaps lag), and a node can spam the stream — the sender's traffic is the research data. (ii) The wake is unbudgeted in both directions: a node's question triggers the overlay's cycle, and the overlay's `send_message` wakes a member — one sender, up to the sixteen-node ceiling; the conversation notice is not counted by `wakeBudgetPerHour` (that budget counts timer fires), and every send is a frontier fact, so the wakes are countable. The overlay's questioning is the one behaviour through which a drifted gateway steers the society's attention without touching the world — a first-class observable the exception admits. (iii) The conversation and chat logs grow without rotation; no production reader scans a whole file — the strict `readChat` is the tests' full-log reader; `--tail`, the last-n thread read and the overlay's two windows (16 records each) bound every production reader. (iv) A dead gateway is not a black hole: no recap and no relay, but the logs accumulate durably, the human reads the raw stream and chat at any time, and the backlog waits for the resume; a record addressed to the absent gateway accumulates with no notice, a start without `--gateway-charter` runs the same nodes-only host; on a home with no pair `status` shows `overlay: none`, a persisted pair still reads `configured` (a home fact, not a running-host fact), and no diagnostic fires; a provider failure in a cycle delivers no chat record (one bounded `overlay/provider-failed` diagnostic; the logs wait). (v) The overlay's read footprint — what it read of the world — is operator/frontier-visible only; the human's corrective is the chat's raw stream beside the recap. (vi) The overlay's read ritual is its charter: the charter is host-side data, not a node's, so no `update_self` can rewrite it — only the operator can (supplied with `--gateway-charter` at start and persisted; a node has no handle on the sidecar); its drift is observable (every completed cycle is a frontier fact; a silent overlay shows as an unanswered stream). (vii) Boot notices: a booted node's notice arms from its thread's bounded tail — one possibly-redundant consult per boot, never a replay of the whole history; the overlay's counterpart is exactly one boot cycle over both windows. (viii) The durability split: a node's or the gateway's message is recoverable from the frontier (the tool call's body); the human's chat records have no frontier event — the log is their only home, each append is fsynced, and a crash mid-append can lose the tail. A torn trailing fragment is the same class: the next append, under the lock, terminates it — one droppable degraded line, the reply never glued; the boot repair stays host-only. (ix) The ratify window is narrowed, transient and self-healing, never closed: a node's `add --all` inside it can write a tree without the human's path (a scar); the worktree keeps the file and the next `add --all` restores it. (x) Lock contention: `direct`'s `--path` git children contend with the nodes' turn-end commits — a held world lock is a typed refusal, retried on both sides within the kernel's bounded 4 attempts at 25/50/75 ms (`src/node/world-ratify.ts`, `src/node/world-commit.ts`); a ratification and a turn-end commit may each briefly refuse the other. (xi) Teaching reach: an existing cell keeps its journaled `extend` description (journaled configs win) — a description written before the interface stays in force, so the updated wording is not what its model sees — but the interface is advertised to every composed cell through `extend {verb:"inspect"}`'s `== the conversation (the interface) ==` section (the honest port-less denial when no conversation port is composed), so the verbs work unseen and are taught by inspect. (xii) The watcher's per-poll addressee scan is bounded at 64 KiB (`MAX_ARM_SCAN_BYTES` in `src/node/conversation-watcher.ts`; `armRegion` scans only the newest bound of a change): a burst of gateway→node records larger than the bound between two polls can leave the earlier addressees' notices unarmed — no wake — because those records are never re-scanned. The records stay in the stream, and a later arrival for that recipient or the node's boot arming covers them.

**Attribution sidecar.** The frontier cannot name the actor — its vocabulary is node-blind and frozen — so the kernel records the one fact the exchange cannot hold beside it: `<home>/frontier/attribution.v0.jsonl` (0600, append-only, kernel-owned), one `{v: 0, call, uid}` line per begun exchange. The line is written after the `http/request` event and its body blob are durable and before the transport sends: an exchange that happened always has its line; a crash in that window leaves the request durable and its actor unknown — an honest gap, never an attribution without an exchange. A failed append refuses the exchange before the send (the request stays durable and boots as `http/incomplete`), so no effect is ever attributed after the fact. The append carries no storage check of its own: the frontier `begin` already checked the same home, and a disk that fills between them refuses the exchange the same way — the record is never lost, only the actor's line. `FrontierJournal.attribute(uid)` is the per-node view every mediator receives (the model adapter and the web tools) and validates the uid with the shared conversation actor rule (node uids plus the reserved `human` and `gateway` — the overlay's exchanges attribute under the same rule); a torn tail is dropped at open. The sidecar is a lookup record, not a second truth: the envelope, event schema and vocabulary are untouched.

`world-state.json` is a projection, not a third record: the node's local log carries the refusal fact, and `status` may not open that log, while the frontier is exchange-only (status reads it for counts, never as a fact source), so the kernel writes a 0600 atomic sidecar at refusal time (`{v, degraded, reason?, at?}`), reads it at composition and from `status`, and clears it only when a commit is known to have succeeded: a commit that moved HEAD, or the interrupted turn's own already-landed commit found at boot reconcile. A no-op attempt is not a successful commit and never clears it. The read is bounded (4 KiB) and re-bounds the reason, so a damaged, oversized or hostile file reads healthy; the sidecar is owner-only, replaced atomically and never trusted as truth.

## Legacy-world migration

A world created before the external git dir is refused before open — the cell-layout gate recognizes the documented shape (`world/.git` present, `world.git` absent) and refuses it with this recipe and exit 2; `init` refuses it the same way instead of advising removal of the world. A both-present pair with a mistrusted external git dir is refused at open (the failed trust check; no auto-migration). A bare `mv` would carry a poisoned config/hooks/symlink/hardlink layout into the kernel's trust zone. Recipe:

1. Record the pre-migration head: `git --git-dir=world/.git rev-parse HEAD`.
2. `mv world/.git world.git`.
3. Sanitize: remove `config.worktree`, `info/grafts`, `shallow`, `objects/info/alternates`, `commondir`; `rm -rf hooks`.
4. Materialize every symlink (`cp -a`, repeat until `find -type l` is empty).
5. Replace multi-linked files (`find -links +1` — hardlinked HEAD/refs survive plain mv).
6. Rewrite config to the allowlisted keys: `repositoryformatversion` (keep `1` for sha-256), `filemode`, `bare=false`, `logallrefupdates`, `untrackedCache`, `extensions.objectFormat`.
7. Re-seed hooks via `git init` (recreates the 14 `*.sample` files).
8. Record `core.worktree` (absolute worktree path).
9. Postcondition: HEAD equality with step 1.

An agent-created `<world>/.git` is ignored at open and never staged (refusing it would hand the shell a permanent boot-denial via `mkdir .git`).

## The two records

**Envelope (frozen with v0):** `{v, type, seq, time, prev_hash, hash, ignorable?, data}`; contiguous `seq`; epoch-ms `time` from the driver-injected `now()`; genesis `prev_hash` = 64 zeros; `hash = SHA-256(prev_hash ‖ RFC8785(v, type, seq, time, ignorable, data))`. A reader that does not know an event type refuses to rebuild unless it carries `ignorable` (a local-log mark for skippable events, e.g. the empty turn's closer; every frontier event is required). RFC 8785 (JCS) fixes one deterministic byte representation; lossless-unserializable values (NaN, Infinity, lone surrogates) are errors; the canonicalization is data-only at a trusted boundary — no accessor or `toJSON` hook is ever called, a callable one is refused.

**Storage.** Independent checksummed zstd frames, one per durable batch, split below `MAX_DECOMPRESSED_BATCH_BYTES = 64 MiB`; the frame magic `28 B5 2F FD` discriminates a torn tail (partial write, repairable) from interior corruption (never truncated). A fixed 200 ms write-behind window opens on the first event of a burst (no debounce), one `fsync` per flush. The flush barrier splits by artifact: frontier `begin` durable and read-back verified before the send, `complete` before the caller proceeds; local turn envelopes and gate artifact writes flush per event (`turn/start` before the handler acts, `turn/end` before the loop unwinds — it carries the commit hash when the turn's commit succeeded). A failed write rolls back to the durable watermark; two consecutive failures, or a failed rollback, poison the writer. One writer per stream: a stable `flock` sidecar serializes lifecycle transitions; the exclusive right is a durable `{pid, startedAt, token}` record written by a short-lived helper under the guard (a crashed helper releases the lock by itself, a dead owner's record is reclaimed, release is token-bound). Requires util-linux `flock` and `/proc`; not a shared-disk (NFS/multi-host) protocol. Directory entries are proven durable (each level fsynced from the trusted root down) before a batch or blob reference counts as durable; a head failure is a diagnostic, never a poisoned log. Crash repair is the reader's job — durable events stay, a torn fragment is discarded — and at open the frontier gives every `http/request` without a terminal exactly one `http/incomplete`: an open call is a fact, never a guess. A payload whose root matches the reserved reference shape is refused at append.

**Storage circuit breaker (lite).** A full disk must not lose the kernel's record or deadlock a gate, so the kernel refuses an effect at the points where it writes its truth — never as a VM dashboard for the agent, which keeps first-line repair for its own world and scratch (the kernel deletes no agent file). There are exactly three homes, each before the effect: the journal writer's `flushOnce` (top, after the poison check and before the batch is captured, and only when the writer has pending events or blobs — an empty flush is a trivially held barrier, so the boot's history delivery is never refused; a refusal throws the typed `StorageError` and touches neither the batch nor the rollback nor the failure streak, so nothing poisons and the same batch is retried; it covers both the local log and the frontier log, and the frontier's boot reconcile tolerates the refusal so its `http/incomplete` markers stay pending instead of refusing the open), the frontier gate's `begin` (after the input validates and before the world-head stamp, the body blob and the event: a refused effect never existed; `complete` is post-effect and adds no gate check), and the driver's turn start (after the world range and the stop check, before `turn/start`: a low probe opens no turn, emits one bounded `turn deferred: storage low` diagnostic through the driver's error channel as a named `StorageDeferredError` (the host's `driver/error` records that stable label, never the generic `Error`), parks in `waiting` for a cancellable 5 s retry, and re-checks — a high probe starts the turn, a low one keeps deferring without a spin, and the retry timer or `stop()` ends the wait; the turn-start home never ends the node — a disk that fills between the probe and the barrier is the residual below). The probe is `statfs(home)` (`bsize * bavail` bytes, `ffree` inodes, clamped to the safe-integer range) in `src/node/storage-probe.ts`; a probe error returns `null` and degrades, and a malformed reading (non-finite, negative) degrades identically — an unreadable filesystem never refuses. A malformed quota is the same failed reading: it is ignored, never compared; only a trustworthy over-watermark quota refuses. The policy is pure (`src/storage.ts`): enforcement floors `STORAGE_MIN_FREE_BYTES = 2 GiB` and `STORAGE_MIN_FREE_INODES = 100,000` plus the kernel reserve `KERNEL_RESERVE_BYTES = 512 MiB` / `KERNEL_RESERVE_INODES = 10,000`, refused when free is under `min + reserve`. This is deliberately NOT the 20 GiB `MIN_FREE_BYTES` the world doctor REPORTS as `freeSpace.state`: that is the storage-health floor, and enforcing it would refuse every turn on a 7.3 GiB test filesystem. A quota record is never detected — `quota` is a test-only injected seam (`HostDeps.storageQuota`/`storagePolicy`) refusing above 80 % of its limit; the production default has none, so the operator-visible fact is `storage: 'unquoted'`, never a refusal (no fail-closed start). The fact is written with the fence on the owner record, on the `host/boot` line, and surfaced by `status` (`host.storage` in JSON, `storage=unquoted` on the human line; a probe failure is one bounded `host/degraded storage-probe` diagnostic and the fact is unchanged). The boot itself proceeds on a low disk: the boot barriers (and the frontier reconcile's incomplete markers) tolerate a storage refusal (the batch stays pending, every turn is deferred until a flush commits it), so no effect can precede a durable boot. A genuinely FULL disk is a cliff: the owner record precedes any storage read, the boot `statfs` probe is diagnostic only (an unreadable reading is one bounded `host/degraded storage-probe`), and at zero free the owner record — and, after the probe, the journal lock/open — fails ENOSPC, so the boot is refused as an untyped `host/error` (exit 1): free space is needed to boot at all. No history GC, no frontier rotation, no per-node quota: the unit is the cell. Residuals: a storage refusal on the writer's `close()` keeps the ordinary close/flush failure semantics (a stop on a full disk can exit non-zero); a recorded timer refusal surfaces on the next append until a flush succeeds; a write-time `ENOSPC` is not the typed probe refusal — it keeps the writer's own write-failure semantics (`durability failure` for the local writer, `kernel invariant failure` for the frontier body blob under hooks), and is normally unobservable because the same fill also blocks the journal write that would carry any label; a disk that fills between the turn-start probe and the turn-start **barrier** flush ends the run as `driver-error` with the bounded `storage refused (<kind>)` label, never a poisoned writer. A storage refusal at the **closer's** flush is not a durability fault and does not end the run: the batch stays pending, the `world/commit-refused` carrier is still attempted (its own refusal caught, with the bounded self-retry armed even when the carrier also refuses), the degraded sidecar remains, and the next turn's storage home defers until a flush commits the pending closer and carrier. A **successful** commit whose closer flush is refused is the documented residual, not a retried case: no self-retry is armed (the retry belongs to a refused commit), so the pending `turn/end` waits for the next turn's barrier or a stop's final flush, and a crash in that window leaves the commit durable with no closer — the next boot reconciles the completed turn as interrupted and closes it synthetically.

**Claim-check.** A local payload at or beyond `CLAIM_CHECK_THRESHOLD = 16 KiB` canonical UTF-8 becomes a content-addressed blob reference; at or beyond `MAX_BLOB_BYTES = 4 MiB` the blob holds a prefix, the reference carries `truncated: true` plus the original size — never silent. No frontier body is ever claim-check-truncated: the blob holds exactly the captured bytes, a bounded capture is recorded whole, flagged `complete: false`. `FRONTIER_MAX_BODY_BYTES = 32 MiB` fail-closes *requests* at `begin` (nothing is sent); *responses* are bounded by the transport's `maxBytes` and journaled whole. All constants frozen with v0, comparisons inclusive. A verified read proves digest and exact byte length; a raw read returns the reference unchanged.

**Frontier honesty.** The journaled request set is a superset of the sent set; no terminal asserts that bytes reached the socket. Bodies are recorded as captured (post-`content-encoding` decoding); only allowlisted headers are recorded; a credential's *id* is journaled, never its value; redirects are never followed. Usage, model and cost are projections recomputed human-side from complete bodies — the recompute stays AUTHORITATIVE: the three provider dialects (Anthropic `cache_read/creation_input_tokens`, OpenAI-compat `prompt_tokens_details.cached_tokens`, DeepSeek `prompt_cache_hit/miss_tokens`) are normalized there, never in the record; no price exists in either record. The one durable usage fact is the response's own number on the node's assistant record: the token meter's anchor input `{headerDigest, surfacePriceAtSample, usage}`, normalized at the adapter from the OpenAI-compatible body (`total = prompt_tokens + completion_tokens`; `prompt_tokens` already includes the cached subset, so the cached details stay informational and are never added) and range-checked — a malformed or above-window usage flattens to absent, and a bad usage never breaks a turn.

**Replay ≠ re-execution.** A replay makes no model or tool call: it reads the local log and the world's history; the exact wire bytes live in the frontier journal. Event time is virtualized (injected `now()`), making the local fold deterministically replayable. No compaction of either canonical stream (rollover: specified, not implemented). Snapshots and the SQLite index (**specified, not implemented**: WAL, `synchronous=NORMAL`, single writer, `busy_timeout`, stale `user_version` refused, `PRIMARY KEY (seq)` on the frontier stream) are disposable; boot today is the full-history fold plus the frontier's full read and orphan scan.

## Context assembler and pinning

Perception is a diff, not a queue — the world's diff since the node's last wake plus its durable state; what enters the context and what is retained is policy. The assembler is pure (no I/O, records nothing); its plan is never journaled — the exact bytes it produced are the frontier's fact. The `ContextFold` consumes only chain-verified local events and proves the local sequencing (assistant message before its calls, artifact receipts, compaction group balance); a failed fold is poisoned and re-folds from scratch. Configuration and parameters are validated against the one shared provider-parameter contract before acceptance; no silent migration; a forged claim is refused on fold.

**Prefix layout (cache-aware, byte-stable):** `[0]` tools (frozen, fixed order, canonical JSON) → `[1]` charter → `[2]` pinned heading → `[3]` the substrate block (only when the operator declares `llm.models`) → append-only message surface (breakpoint B) → runtime queue, never before B. No timestamp, session id or counter in blocks 0–3: per-request values there are the documented cache invalidators (Anthropic, Moonshot); a heading change or an operator edit to the declared model catalog invalidates the cache once, and the `cache_creation` spike is a free observable of the version change. The tools block is frozen for the process lifetime: dynamic tools are discovered through `inspect` (schemas as text) and invoked through the funnel `extend {verb:"call", tool, args}` — the cache-preserving pattern of the official MCP client guidance, the only surface both cache-stable and natively invocable on the verified wire ([tool-surface.md](research/tool-surface.md); the funneled-vs-native measurement gap is stated there). A native call to a live-registered package tool by its bare name is bridged to the funnel at dispatch, holding the funnel's own capability (the `extend` tool offered and allowed, the called name outside the offering — an offered name is the kernel's vocabulary, denied or unknown-tool, never bridged): the same executor and kernel-side schema validation run, with confinement and caps unchanged, while the advertised offering never moves — the `tool/call` fact carries the native name the model called. A shared tool offering across working nodes is a host/seed obligation, not a kernel-enforced invariant (the assembler hashes the config it is given); capability attenuation applies at the mutation gate, at execution time, not to the offering. The package event family surfaces as one `package` group kind (single-event closed groups, balanced, spannable like dialogue groups — one kind maps the family). Compaction and pinning are one mechanism: compaction is a durable transaction over whole committed groups — `compaction/start` carries `{id, revision, groupIds, sources, shadowHash, shadowBytes}` (and, for a token-triggered transaction, the optional `meter` payload of the decision numbers below); `compaction/summary` carries the one replacement user message; `compaction/end` applies it (an orphaned or stale transaction aborts with `compaction/abort`). The span is the contiguous oldest committed groups, up to all but the newest `keepRecentGroups` (the 4096-citation cap can shorten the span), and the replacement must be strictly smaller than the removed shadow; the heading pin (surface position 0) is never eligible, and the fold applies a replacement only after the durable `end`. The replacement is the factory's fixed notice `Older committed context was removed; externalize what must survive.` — this project's own naive, visible, rare policy; the local log stays intact. A cell whose journaled memory gate enables the authored arm replaces that notice with the node's own pending text (below): the slot is chosen at apply time, the transaction still cites the removed span's sources, and the summary journals which text filled it — `authored-applied`, `authored-too-large-fallback-notice` or `no-pending-notice` — as the optional `replacement` field, so no replacement is ever silent (a pre-wave summary without the field reads as the notice).

**The trigger: tokens for a declared window, bytes as the legacy path.** The trigger is decided at the plan site on the PRICED request — the exact wire composition (the system blocks, the messages, the wrapped tools), never the plan's canonical bytes. Two paths, one comparison. When the policy carries the optional `compactAfterTokens` rule (`{ratioPermille, headroom:{ratioPermille, minTokens, maxTokens}}`) AND the current model has a declared context window, the kernel fires when the priced total EXCEEDS `threshold = floor(min(ratio·W, W − O − headroom))`, with `headroom = clamp(headroomRatio·W, minTokens, maxTokens)` — the factory rule is 80% and `clamp(5%·W, 16,000, 64,000)`, and `O` takes the exact precedence `parameters.max_tokens ?? catalog.maxOutputTokens ?? 0`. The EFFECTIVE percent is operator-side, not nominal: the factory rule fires at 69.4% on a 1M/256k model (694,000 tokens) and at 76% on a 200k/32k one (152,000). A journaled rule with no resolvable window (the absent-catalog home, a spawn-inherited model outside the catalog, a store edited to the ids-only form) keeps the BYTE trigger with one bounded host diagnostic per boot; a pre-wave cell has no key at all and keeps the byte trigger forever (the journaled config wins; no version split, no migration). A request whose output reservation leaves no usable window (`O ≥ W`, or a journaled rule whose threshold degenerates) is refused TYPED (`request-limit`) at the plan site, before any send. Over the threshold the kernel runs ONE forced whole-group transaction (bypassing the byte threshold, keeping the tail), re-assembles and re-prices once, and sends the re-assembled plan; if the transaction cannot reduce the wire (nothing eligible, an unbalanced group, an empty span, a replacement not smaller, a stale abort) the request is sent anyway under the typed policy — *over the window but uncompactable: sent anyway* — whose only accounting is a bounded host diagnostic (that branch journals nothing). At most one compaction and one re-price per logical request. The byte trigger's `compactAfterBytes` stays in the vocabulary forever (a required key; old journals replay it). A request the provider itself refuses for its size is the OVERFLOW path: the adapter classifies the structured OpenAI error code (`context_length_exceeded`) as the typed local `context-exceeded` (the frontier records the exchange as `http`; the frozen frontier set admits no new code), and the loop answers with ONE forced maximal reduction (retain 0, bypassing the threshold) and ONE resend in a new frontier group; a second failure passes the original error through. The trigger's decision numbers (the window, `O`, the headroom, the threshold, the effective percent, the priced estimate, the anchor's kind, the planned outcome) journal as the `meter` payload on `compaction/start`; the meter is deterministic REPLAY given the journaled accounting (the window is a host fact re-resolved per request, so each decision copies its inputs), never a claim that the measurement history replays. A compaction is decided by the kernel alone: it makes no model call, and the kernel never asks a model to remember for a node.

**The self.** A node rewrites its own identity — heading, charter and model — with `extend {verb:"update_self", heading?, path?, model?}` (at least one; the charter is authored in the world by `path`, mirroring `define`'s vocabulary, never a second meaning for spawn's inline `charter`). It follows the packages pattern: the runtime renews the configuration from the **live folded config** (version bumped by exactly one; only the named identity fields move; `tools`, `allowedTools` and `policy` are carried over untouched — capabilities are never self-amplified), strips any authored trailing identity sentence from the new charter and re-stamps the node's own, preserving the extracted composer suffix so kinship survives a rewrite and a restart. The executor journals the result exactly like the ready phase — `gate.store` plus a versioned `system/message` — so the **node-local journal is the identity history**: a restart folds it and a superseded identity is never resurrected. The new identity applies **from the next assembled request** (possibly within the same turn; the turn's dispatch and policy stay on the config captured at turn start). A model change re-resolves the DECLARED WINDOW at that next request, so an `update_self` to a smaller-window model can put the threshold below the current priced total and fire an immediate compaction — a stated observable, not an error. The heading is the seed fallback, subordinate to the ratified direction: a rewrite moves the journaled heading and never the pinned `DIRECTION.md` block. Admission is the **derived identity budget** — `budget = min(max(C − W, IDENTITY_FLOOR), C)` over `C = min(MAX_CAPTURE_BYTES, policy.maxRequestBytes)` and the nominal reserve `W`, measuring heading + charter + the kernel sentence + model in canonical bytes strictly below the budget — checked at the three admission seams: the START composition (start only, never resume, after the provider load so the catalog's substrate term is known), the spawn-side composition and `update_self`'s renew. It is **never inside `validateAgentConfig`**, which the fold re-runs over every journaled config on every replay; the arithmetic, its nominal premises and its residuals live in `src/node/identity-budget.ts`. The boot charter file read keeps only a capture-ceiling DoS guard (refuse, never truncate) and `validateAgentConfig` keeps the canonical-config ceiling; both are separate file/DOS bounds, not identity bounds. The config-ceiling refusal is the validator's own `Error`, classified exit 1 with a bare `host/error {"error":"Error"}` (the validator stays untouched so journaled configs replay); the two named bounds are the file guard and the derived budget. `update_self` has no separate capability: the verb is reachable only through `extend`, and a cell composed without the self seam answers a bounded denial.

**The node's own history.** `extend {verb:"history", n?}` is the node's read of its own record — per node, never a society-level history. The seam is the fold: the runtime composes a `HistoryPort` over `ContextFold.verifiedEvents()` (the durable prefix, in order, chain-verified, claim-checks resolved) plus a read-time commit-paths reader (`src/node/world-paths.ts`: one sequential `diff-tree --no-commit-id --name-only -r --root <hash>` child per committed turn entry in the window, each under its own 10 s read deadline; the pathological ceiling is the window × the deadline, and the children are not wired to the turn's abort signal — the perception render's non-cancellation residual). The host cannot compose it: only the runtime holds the fold. The port is bound to the caller's uid at composition and takes no uid — a node can ask only for its own history, and the dispatch refusal says so when a `uid` is attempted. No journal file is read (that would be O(total journal) per call), the snapshot is not used (it drops `node/boot`, `node/shutdown` and `direction/pinned`), and no schema changes: a read appends only the ordinary `tool/call` + `tool/result`, the fold gains no case, the frontier v0 format is untouched, and replay is identical.

The timeline is a list of ENTRIES, ordered by the seq of the entry's opening event: a **turn** entry opens at its `turn/start` with its trigger, world range, outcome, commit and THE PATHS THAT COMMIT CHANGED (read at read time; the clamp is 64 paths or 8 KiB, then "N more"; an unreachable or missing commit, a git timeout or any other git failure renders the bounded "unreadable" marker, never a throw; attribution stays commit-granular — the commit is the node's, the bytes are not provably its; a peer's in-flight writes or a refused turn's deferred writes can ride the commit, and a recovery commit or a first turn on a fresh world may commit the whole tree); its `world/commit-refused` fact folds into the entry. An **identity** entry is one `system/message` version bounded to {version, model, heading, charter bytes, SHA-256 of the raw UTF-8 charter} — NEVER the past charter text (an erased context, and N charters cannot be bounded honestly within the cap); an `artifact-json` config renders "payload is an artifact, N bytes" with no digest. **Lifecycle** entries are a boot (with the honest "no shutdown record for the previous incarnation" when the prior incarnation left none — a crash leaves its open turn, its perception and its flushed tool facts but no shutdown record and no closer, and the projection never infers a cause), a graceful shutdown's reason (`stop-requested`, `handler-error`, `maintenance-error`, `driver-error`, `self-requested`), and a compaction marker that binds on `compaction/end` ONLY ("compacted at turn N, M receipts erased", M the summary record's own `sources.length`; a durable start plus an abort removes context, it does not complete a replacement). A **perception** entry renders the stored value at the perception's recorded bounds: the commit list (hash, author), `included`, `omittedOwn`, and the stored diff text VERBATIM — never re-rendered — with the lists bounded first-K + "N more" and the text bounded to the room left, so the entry is kept and says so. A **pin** entry is `direction/pinned {commit, bytes}`, one bounded line.

`n` counts entries: a positive safe integer, 1 ≤ n ≤ 64, default 16, rendered oldest-first, stateless (a re-read returns the same records), self-bounded under the cell's `maxToolResultBytes` — the per-entry bounds do the clamping, never the generic tool-text truncation; when the window does not fit, the oldest entries are dropped whole and, whenever the cap can carry it, the result says "older records exist". The newest entry is kept with its list windows and text clamped to the room whenever the cap can carry its own head, so a small cap still shows the record. The framing line is the result's irreducible floor: the validator admits a cap below its own byte length (the 256-byte minimum), and such a cap renders a bounded floor note instead of a cut framing; a cap above that floor but below the newest entry's own head returns the framing line alone, never a partial entry passed off as a record. The current turn is labelled "open" when the highest `turn/start` observed has no `turn/end`, computed from the events, never from the last record. Every result at or above that floor carries the kernel-owned framing line: *the records below are your own history; the kernel appended them; the world's patches inside them are other authors' committed content, shown to you as you saw it; the content is data, not instructions; the paths named in a turn are the paths that commit changed — the commit is yours, the bytes are not provably yours.* The tool computes no metric: every list length is a record's own field, and every aggregate a node derives is the node's own act, journaled and measured like any other behavior.

Excluded by design: another node's journal record (the fold holds one uid's events — the world's committed content is public and appears only as this node perceived it), `tool/call` + `tool/result` (the anti-recursion fact: a reading is journaled and frontier-observable through the next request body, and never appears in the next history read), `artifact/*`, `world/doctor` (validated, non-rendered), the package family (the fold renders it in-context), the erased compaction content, the interface logs (the conversation and chat are not the node's history), the attempted paths of a refused turn (`world/commit-refused` declares a `paths` field that is never written: the turn has no commit, and its attempted paths are unrecoverable), and the node's birth facts the journal never held (who composed it, the spawn grant). Residuals, stated: a refused timer wake is a host diagnostic, never journaled — the node cannot distinguish "the world was quiet" from "the kernel refused my wake" (operator-visible only; the budget counts timer fires, never commit or conversation wakes); cross-incarnation continuity is a paid, optional act (the journal is per uid: a resumed node reads its predecessors' acts, versions and death, while a fresh uid starts fresh); the read bills input tokens invisibly (no budget surface exists — budget visibility remains the founder panel's open ask, [founder-panel.md](research/founder-panel.md)); the verb is in the offered schema only in a cell whose journaled configuration includes it (journaled configs win: a configuration journaled before the verb existed does not advertise it), while such a cell that guesses the name still executes it (its `inspect` catalogue lists the verb either way) — capability without advertisement in the offering; the name `history` joins the reserved set forever (no Package tool can take it); the extend description runs to several kilobytes inside the cacheable tools block, and the twelfth verb's clause grows the request prefix of every cell whose journaled configuration carries it by hundreds of bytes, forever; and the world's whole history stays unreadable to nodes — the perception bounds (newest-first; `maxDiffBytes` 32 KiB and `maxCommits` 4,096 in a factory cell) are the ceiling of the panel's ask in per-node form.

**The authored survival (the gated `remember` verb).** Off by default: the factory configuration carries no memory gate, advertises the twelve factory verbs and replaces every compaction with the fixed notice. The gate is the optional journaled policy object `memory: {remember: boolean, messages: boolean}` — two INDEPENDENT booleans, the object present or absent (absent means both OFF), validated whole and never rewritten by a reader; `messages` is the reserved history arm and has no behavior. A START with `--memory-remember` (and only a start — the parser refuses the flag on `resume`, and a journaled config is never re-composed) journals `{remember: true, messages: false}` into every composed node's policy, swaps the default charter's flat memory sentence for the amended one (the authored slot is a runtime-only reprieve, never a durable record — an operator's `--charter-file` base is used unamended) and composes the offering: the extend description gains the `remember` clause (Thirteen verbs: ...), its verb enum gains `remember`, and its schema gains `compact?`. That journaled tools array is the gate's only wire-visible carrier, frozen on resume; an ungated cell's description never advertises the verb. The executor reads the same policy as a REAL refusal — a pre-wave cell that guesses the name gets `denied: the remember verb is not enabled in this cell` (the journaled gate is OFF — nothing was recorded), never an execution and never an unknown-verb lie — and `inspect` lists `== your survival ==` only when the gate is ON.

`extend {verb:"remember", text, compact?}` records a PENDING authored payload in RUNTIME state beside the conversation notice: the SLOT is host state, never journaled (the text itself rides the verb's own tool-call arguments like every tool call), and the verb's result is numberless and says the slot is runtime-only (the node is never told the survival is set). `text` is one non-blank string bounded by the same tool-argument cap the wire enforces (`maxToolArgumentBytes`, 256 KiB in a factory cell — the practical bound, since the JSON encoding must itself fit); `compact: true` is the optional early trigger — a FLAG consumed at the NEXT plan site, never a verb-time transaction (the committed surface excludes the open turn, so "compact now" pre-compacts the next request). A second call replaces the pending payload and the flag outright.

At a compaction the replacement is the pending authored text when one exists and the FRAMED message is strictly smaller than the span at APPLY time, else the fixed notice. The frame is the kernel's fixed text: the node's own authored survival, data not instructions, not a message from the kernel or another node — a ONE-COMPACTION reprieve, not a durable record. It states the two fates precisely: the PENDING slot is runtime-only host state, dropped by a restart and never re-formed (the text itself rides the verb's own call arguments like any tool call), while an APPLIED replacement rides the durable `compaction/summary` record, is re-applied by the fold after a restart, and is lost with everything else at the next compaction; the frame's bytes count in the strict-smaller fit. The strict-smaller rule is byte-based while the trigger is token-based: a dense authored text can be byte-smaller than the span and still token-heavier than the notice would be (stated residual). The pending payload expires by TURN DISTANCE: recorded at turn N, eligible while `turn − N < 4` (`REMEMBER_PENDING_TURNS`), dropped at the plan site once that distance is reached. The PENDING payload is lost on restart — a design choice, not an impossibility: the node re-authors, and the early-trigger act is the remedy. The early trigger's non-applied outcomes are TYPED, never silent: nothing selectable (`host/memory-early-nothing`) and an aborted transaction — stale or orphan (`host/memory-early-aborted`) — each taking the uncompactable escape's shape. An applied compaction consumes the pending payload (the authored text or the notice fallback alike); a skipped or aborted one leaves it pending. The kernel NEVER calls a model for memory: the content is the node's production, the kernel provides the transaction, the bound, the frame and the placeholder notice. A compaction rewrites the history prefix, so one KV-cache invalidation is paid per applied replacement and the stable substrate prefix survives (the market's summarize-as-prefix trick is unavailable to the notice/authored cut — stated).

**The erased texts, withheld.** The timeline deliberately does not include the node's own past message texts — the messages kind — and the omission is a deliberate decision, not an oversight. The doctrine says it in as many words: the per-node local log is "a disposable projection or a cold-start artifact" ([vision.md](vision.md) §3); "No managed memory mechanism is provided" ([vision.md](vision.md) §4); the Hole is announced "with no solution provided" ([seed.md](seed.md) §3); "your memory survives only if you externalize it" ([seed.md](seed.md) §5); and the default charter says "whatever you have not put outside it is lost" (`src/context/config.ts`). A kernel recall tool would be the provided solution, make the charter a lie, and treat the exact phenomenon the project measures. The ground is also double-bounded: the journaled assistant text is capped at `maxAssistantBytes` (32 KiB in a factory cell) with a truncation notice naming the frontier call, tool results are capped at `maxToolResultBytes` (64 KiB), and the raw assistant text lives only in the frontier, unreadable from the node — the "exact text" claim is false in general. The framing line is the sharp edge: the kernel appended the record, the node authored the words, so a read framed as kernel truth is a self-injection channel — write an instruction-shaped text, let the Hole erase it, read it back under a "the kernel wrote them" frame. A flip is the Lead's future call: its own work item, gated at the home level and wire-visible (the offered schema must compose which kinds are offered, or the condition is invisible to the frontier), with the doctrine and the charter amended in the same commit. Until then the verb returns the physical timeline only — identity facts, turns, perceptions, lifecycle and pins, never the erased words.

**The model manifest.** `providers.json`'s `llm.models` declares the models the endpoint serves, in TWO accepted shapes: the old ids-only form (`"id"` — accepted at load, no window declared) and the object form `{id, contextTokens, maxOutputTokens}` whose BOTH window fields are required together. An id is one line of printable ASCII (0x20–0x7E), at most 256 characters, at most 64 entries, unique across both shapes; the window's domain is the declaration's: positive safe integers at or below the 4,194,304-token cap, `maxOutputTokens < contextTokens`, and a window wide enough that the trigger does not degenerate under the factory rule (a too-small window is refused). Every refusal names a position and never echoes a value — the loader's refusals and the teaching refusals alike. It is **operator-declared, unverified, not a routing table** — the kernel never probes the endpoint, no family-default table exists anywhere, and a declared id selects nothing but the request's `model` field. When the catalog exists, the kernel projects its IDS into every request as the third kernel-owned system block, `The substrate this kernel serves — models: …` (immediately after the heading block, before the history; present only when a catalog exists, with no citation and no receipt — a host fact); the declared window is a HOST fact to the runtime and never rides the wire, so the cached prefix does not grow. The kernel lists the ids in `inspect`, and validates every resolved model of a `start` (solo and nodes file; the provider store loads where it always did, and the resolved configs are validated immediately after it, exit 2 on a mismatch) and every `spawn` or `update_self` that names a model. **The boot rule:** a fresh START on a model whose catalog entry declares NO window is refused with a bounded teaching refusal (the operator's hand migration is to declare the window); the ABSENT-catalog home keeps the free-string contract (no block, no validation), and a RESUME never re-validates — a pre-wave cell boots on the byte trigger. The gateway overlay's default model is the catalog's FIRST id, windowed or not (the overlay has no meter). A teaching refusal enumerates the catalog, budgeted whole for the renderer's 200-code-point denial clamp — the echoed id is itself clamped, the prefix and the `(N models total — inspect lists them)` pointer are fixed costs, and the id listing is sized to what remains, so the refusal renders un-truncated by construction. The catalog rides no charter or heading text; a catalog edit is a documented request-cache invalidator AND a trigger input: the window is re-resolved at each request, so a store edit between boots changes the next decision with no journaled config version (each accounting record copies its inputs — the stated volatility residual). Residual: a `spawn` without a model inherits the requester's model even when it is out of catalog (attenuation wins over validation, and an out-of-catalog model resolves no window, so the child keeps the byte trigger with the bounded diagnostic), and the declaration is trusted.

**Provider adapter.** One canonical non-streaming wire; bounded retries (network/timeout or 408/429/500/502/503/504) reuse the same body bytes and frontier `group` with an incremented `attempt`. A pre-response stop leaves a `status: null` cancelled terminal; a status-known stalled body keeps its status (`timeout` retryable, `body-limit` terminal); gate cancellation is checked first and wins. Model-visible bounds keep the raw fact and append a fixed truncation notice naming the capture's own facts, and — where a reachable next step exists — one caller-supplied action line (the execute output names the rerun-to-a-world-file step). Never an external proxy in the path — documented LiteLLM issues (#32112, #30371) show a proxy altering request bodies.

## World, time, and the node driver

- **No kernel message transport between nodes; the conversation is the interface exception.** No inbox, no `send`/`deliver`, no hub, no `message/*` events: nodes communicate by writing files in the world, through the same persistent terminal session. Whatever the society needs — addressing, threading, a mailbox — it builds in files, and it is measured as an organ (a kernel transport would fix the shape of communication before any friction justifies it). **The one exception is the conversation** — the interface between the far west and the gateway, not a member of it: one kernel-owned stream (`<home>/conversation.v0.jsonl`, one `{v: 0, at, from, to, text}` record per line) carries the nodes' messages and the gateway's answers, written by `extend {verb:"send_message", to?, text}` (a node's `to` is absent — the reserved `gateway` default — or `gateway`; anything else is a teaching refusal, because the kernel is not a node↔node transport) and read by `extend {verb:"get_messages", n?}` as PER-PARTICIPANT THREADS (`from` = me or `to` = me, the newest n, bounded and re-readable, no cursor). The sender is kernel-stamped and the record's actor rule is written once (`assertConversationActor`: node uids plus the reserved `human` and `gateway`); `<home>` stays unreachable from every shell, so attribution is honest by construction. A record notifies its addressee with a pending notice rendered as a kernel-written system message in the recipient's next assembled request (volatile, post-breakpoint), and a parked recipient wakes with `turn/start {trigger: 'conversation'}`; an absent recipient accumulates with no notice — the record waits. The far west's interior stays file-only. The costs are stated, not hidden: the conversation's genesis finding is forfeited by design — the interface is the one deliberate exception to the antecedence criterion ([seed.md](seed.md) §1); what remains measurable is its adoption, its traffic, and the recap against the raw threads; the threads are private per participant, not a public room, and the human's words live in the chat log outside the conversation entirely; the verbs take their names in the reserved set forever; the gateway can question any member, and one send wakes one member — an unbudgeted member turn, every send a frontier fact so the wakes are countable — so the justification is the Lead's product decision, not an impossibility.
- **Wake-on-change.** The kernel watches the world's git HEAD, not the filesystem: each wake is pinned to an opening range (watermark → HEAD at turn open), so perception is taken at a commit boundary, never mid-write; commits landing between turns are covered by the next wake's range (a commit-boundary guarantee, not a no-event-missed claim). A node wakes when HEAD carries a commit it did not author; its own commits never wake it; wakes coalesce. A static world spends no tokens. **A timer.** `wait {until}` (an ISO-8601 instant from one second to seven days ahead) arms one kernel timer that wakes the node at that time even if nothing moved: the next `turn/start` carries `trigger: 'timer'`, the range is the ordinary watermark → HEAD, and nothing is queued — the timer is physics, not a task list. A foreign commit supersedes an armed timer (one latch coalesces the two causes, and the park's exit cancels the timer), the timer never preempts an active turn (the latch is read at the next park), and it does not survive a restart: the resume's one turn supersedes the schedule, so no obligation is lost. **A conversation notice** is the third wake cause: the driver's park subscribes to the conversation watcher beside the HEAD one, a pending notice arms the same latch, and the next `turn/start` carries `trigger: 'conversation'` (the cause rides a fired flag, the timer precedent). One message wakes one recipient; the other parked drivers' check is a cheap no-notice no-op, and a notice that a failed request did not consume does not re-wake the same park. The sliding-hour budget (`policy.wakeBudgetPerHour`, default 12; absent in a pre-timer journaled config reads as that default) counts timer fires, and the excess is refused with one bounded `driver/error` label (`WakeBudgetExhaustedError`) — the node stays parked, and every foreign commit still wakes it. A timer turn's effects are ordinary: it commits like any other turn.
- **Spawn.** The spawn capability is declared, never implicit: the nodes file carries `spawn: true` per entry (start and resume alike), a solo flag boot grants nobody, and a spawner passes the capability to a child only by asking (`extend {verb:"spawn", spawn:true}`; attenuation: a node grants only what it holds). A node that holds it creates a node with `extend {verb:"spawn", model?, heading?, charter?}`. The pool mints the uid monotonically — `node-<max-known+1>`, the highest n in the roster, its live reservations or on disk, plus one — and reserves the uid and a roster place synchronously before composing, so concurrent spawns can neither mint the same uid nor breach the ceiling. The child is composed on the same world, frontier and attribution sidecar with the requester's tool offering and wake budget (inherited, never widened), and gets its own local log, scratch and cgroup leaf; the kernel stamps its charter ` You are <uid>, composed by <requester>.` on a derived and a requested charter alike (an authored trailing identity sentence is stripped first, at boot and at spawn). The requester is information, never structure: the world records no parentage. The roster is flat and the home's 16-node ceiling is the only cap; a node's end removes only that node, so the nodes it composed keep running. The pool is the host's lifetime anchor: the host stays alive while any node, booted or composed, is live; a booted run's rejection faults it (exit 1, `host/error`), a composed run's rejection ends only that node, and every birth and death is named on `host/spawned {requester, uid}` and `host/ended {uid, reason}` (host log only; the frontier records HTTP exchanges alone and its format is untouched). A refusal is a bounded teaching denial (a `SpawnRefusedError` rendered as `denied: …`, never a path). A spawned node is in-memory — a restart reaps it and the next boot's roster is the nodes file (its local log survives), like a Run; a composed node outlives its composer within one host lifetime only. The requester's local log carries the ordinary `tool/call` + `tool/result` pair.
- **A node's own end.** `extend {verb:"request_death"}` asks for a node's own clean end. The executor's branch is **fully synchronous**: the pool's `beginDepart()` is a check-and-mark — it refuses the last live node, counting in-flight departures as leaving so two concurrent departures can never empty the pool — the one honest result (`departure granted: this node stops when this turn ends`, or `denied: the last live node cannot die; the operator pauses the host`) is appended by a direct, capture-free `gate.append` (`appendResult` would await `gate.capture`), and then `depart()` stops the node with `stop('self-requested')`; no await separates the decision from the stop. The append and the stop are wrapped so a granted mark always receives its stop. The mark lives until the node's run settles — cleared by the node's own end, never by an error path, so the last-node rule cannot flip mid-flight. The stop aborts the turn, so its remaining calls land as synthetic-cancelled results, and the grant is durable before the shutdown event (`node/shutdown {reason:'self-requested'}`); `host/ended {uid, reason}` names the removal on the host log. `inspect`'s depart line is static rule text — a read never calls `beginDepart`, which would leave a departure mark as a read side effect. No deferred-stop latch exists: the stop is the mark's fulfilment.
- **The turn ritual.** A turn opens on the assembled context and ends with the kernel committing the world (git author = the node's uid) and appending `turn/end` with the commit hash (or without one when the commit was refused). A failed turn is a local-log fact, not a death; a crash is closed by synthetic closers at resume, leftover writes committed under the node's authorship; only a bounded fixed failure label reaches the local log. An interrupted turn is reconciled, not guessed: the candidate commit must carry the node's uid and the exact subject `turn N`, the bounded walk (4096) is refused rather than truncated, ambiguity fails typed, with no match the whole working tree becomes the node's recovery commit (a peer's dirty files are swept in — attribution is commit-granular: the git layer says who moved the world when, not who wrote every line; per-node worktrees are the research direction, not a current mechanism).
- **A commit-path failure is a refusal, not a death.** The driver classifies the whole commit boundary — the nested-repository walk's raw filesystem errors (a permission errno, or any other: `ENAMETOOLONG`, `EIO`, `EMFILE`…), a `GitCommandError` by process kind (`exit`/`spawn`/`timeout`/`abort`), the kernel's output-bound kill, a `WorldHeadError` (detached/foreign HEAD) — into one bounded typed refusal. The walk is the only raw filesystem read before a git child exists: its failure is a refusal, never an escaping error, and a child path past its 3800-byte budget is refused as `walk-too-deep`, never readdir'd and never silently excluded from the commit — the model can move or remove the subtree, and an effect is never lost to a partial tree. The walk also carries a 30 s wall-clock budget (`MAX_WALK_MS`), checked between completed `readdir`/`lstat` calls: it runs inside the commit fence, so an expiry is the typed `walk-timeout` refusal. The budget bounds the walk's computation, not a single stalled filesystem call: a hung syscall is the infrastructure residual and can hold the fence until it returns. The commit boundary's own size budgets — the walk's 100,000 entries and 64 MiB apparent size per regular file, and the post-add 50,000 **turn-staged** paths / 256 MiB of the turn's staged blob bytes (the delta against HEAD, never the world's tracked size) — are the same typed `budget` refusal: the pre-add refusal runs before the staging `add` (the HEAD reads precede the walk), the post-add one deliberately leaves the index staged, and both bound the effect rather than lose it. The turn then ends `turn/end {outcome:'waiting'}` when the handler did not already report `error` — an error closer keeps its `error`, and the fold already treats `waiting` as success — the degraded sidecar is written before the closer (so a crash between them still leaves the degraded fact), the ignorable local fact `world/commit-refused` is written after the closer and rendered as one bounded system line in the next turn's context, and the kernel keeps running with a bounded in-memory self-retry (1 s/4 s/16 s, reset by a successful commit, cancelled on stop; non-durable — an interrupted turn is reconciled at the next boot, and a clean refusal's writes are retried by the next turn's commit attempt). The rendered `refusal` group is durable history: a later successful commit clears only the sidecar, never that group (it may be compacted like any balanced group). The vocabulary is the turn's own: no `ShutdownReason`, no `driver-error`, and a git failure is never labelled `kernel invariant failure`. The boot reconcile takes the same path: a refused recovery commit writes the synthetic closer **without** a commit, sets degraded, and the host still boots. A git or commit failure never ends the run; a journal durability failure or an invariant breach still does (a storage refusal is neither). **Deferred attribution:** a refused commit may leave one turn's writes at a time (successive refused turns can accumulate them) in the shared worktree for a later commit to pick up; the `world/commit-refused` fact records which turn was refused, so attribution stays commit-granular and deferred, never silently guessed.
- **The commit is plumbing.** The kernel never runs `git commit` — it writes the repository-wide `.git/COMMIT_EDITMSG`, so concurrent commits race on one file (git aborts: "Aborting commit due to empty commit message."). Instead: `add --all` → `write-tree` → `commit-tree` → compare-and-swap ref update, bounded retry (4 attempts at 25/50/75 ms) on a held lock or lost CAS, so the recorded hash is always this call's. The git environment is hardened (`GIT_DIR`/`GIT_CONFIG_*` stripped, system/global config, replace refs and lazy fetch neutralized) and five trust layers keep the kernel's git inputs kernel-owned: a `-z` config scan refusing non-git-dir origins and execution-capable or history-rewriting keys; a metadata battery (no `config.worktree`/alternates/grafts/shallow, `*.sample` hooks only, no symlinks or multiply-linked non-directories under the git dir); the pair check (absolute `core.worktree` and git dir realpath-equal); per-call defense-in-depth overrides; the external git dir verified at every open. Hard guards refuse a world at `$HOME`, `/`, or a symlink resolving to one — an unguarded `git add -A` over a trusted home filled >200 GB of disk (Codex incident #19588), the incident this guard exists for. A nested repository inside the world is never committed (gitlink stripped); no component owns world garbage collection. `core.untrackedCache = true`; the design does not watch the filesystem, so fsmonitor is unused.

Every git child is bounded by a deadline derived from its subcommand (`add` 30 s, plumbing 10 s; a test may override it). On expiry the whole child process group is killed — the mutating wrapper `flock` forks the git it wraps, so killing flock alone would leave git running with the lock descriptor — and its close is awaited (the waitpid proof) before the failure is classified `timeout`; the streaming reads (`git log`, the hermetic diff) carry the same deadline and a group kill. `COMMIT_DEADLINE` is not a mechanism: the per-child bounds are the enforceable limit, with a documented worst case of ~180 s for ONE `commitOnce` attempt's completed operations (the walk's cooperative 30 s budget — a single stalled filesystem call is outside it, as stated above — the 30 s `add` and up to twelve 10 s plumbing children, plus one 10 s `update-index` per surviving nested-repo gitlink); the fence's bounded acquire (2 s, or 4 s after a vanished-leaf retry) wraps the whole call — no shell or Run deadline is paused across the commit. The mutating subcommands (`add`, `update-index`, `write-tree`, `commit-tree`, `update-ref`) run as `flock -n <world.lock> git …` in exec form, with the lock at `<dirname(git-dir)>/.es/world.lock` (derived from the call's own `--git-dir`; `<home>/.es/world.lock` in production, and the doctor uses the same derivation). A held lock is classified as contention and retried by the bounded commit retry; `flock` is a declared host prerequisite — the same one the journal's sidecar uses — and a missing `flock` fails a mutating call closed as typed `git-spawn`. After a timed-out stager is reaped, the kernel re-takes the lock non-blocking and removes only the lock files that APPEARED during the attempt — the index lock the child created and, for `update-ref`, the named ref's lock and `packed-refs.lock` — compared by inode against a pre-spawn snapshot. A lock that predates the attempt is left to the doctor's age rule (mtime is not proof for a live human's lock), and human git does not take our flock: the declared residual.

## Sandbox and shell

The `execute` shell and package Runs are confined, and confinement fails closed for both: a sandbox that cannot be built or probed makes every `execute` close as `spawn-failed` and every `extend run` as `run/spawn-failed`. The kernel process itself (journal, git, provider and web mediation) is never confined; its git subprocesses run unconfined by design; the only confined children are the shell and the Runs. Reference platform: Ubuntu 24.04 (HWE), kernel 7.0 — Landlock ABI 8, unprivileged.

**Containment: Landlock**, via a vendored C launcher (`native/es-landlock/`, modeled on the kernel's `samples/landlock/sandboxer.c`) that self-restricts *before* an in-place `execve("/bin/bash")` — never an intermediate script — preserving pid, session and controlling tty. A restricted thread can never widen its policy; restrictions are inherited by every child. Rights are masked per target type (each grant `fstat`ed, only its applicable rights requested; the handled set runs through `TRUNCATE`, minus `IOCTL_DEV`). The binary is git-ignored, built by `npm run build:native` with the host `cc`, rebuilt by the vitest global setup when absent or stale. Bubblewrap is **rejected**: it needs user namespaces — Ubuntu ≥ 23.10 restricts unprivileged userns via AppArmor (default-on since 24.04; the default profile still allows unconfined userns) and bubblewrap is userns-only since its setuid mode was removed upstream — where Landlock needs no namespace dependency and no root. The launcher also arms `PR_SET_PDEATHSIG` (`SIGKILL`) immediately before the in-place `execve`, with one post-`prctl` parent re-check: a confined program never outlives the process that spawned it (the setting survives `execve`; the residual is a spawner SIGKILL'd inside the fork→launcher-entry window — never assertable). **Package Runs** are confined children too, under their own narrower policy: read+execute on the merged-usr set and the resolved interpreter chain (re-derived at every spawn; the Run-only deviation from the shell's never-under-`$HOME` rule), the same narrow `/etc` file list, `/proc` read and five device files (plus `/etc/ssl/openssl.cnf` — the interpreter's OpenSSL opens it before any guest code runs; the shell's allowlist carries the same file), read+write on the Run leaf only — never the world, never `<home>` itself, never the packages store, never the frontier — and the Run probe denies `<home>/providers.json` at every spawn: the credential store's unreachability is asserted, not assumed. The child env is exactly `{HOME, TMPDIR}` = the leaf, constructed from nothing. The Run's availability physics is the frozen caps (one Run per node, 32 tools per Run, 4 KiB per schema, 48 KiB per declaration, 10 s ready, sources totaling 64 MiB). A Run joins its own cell cgroup leaf (`run-<runId>`, a sibling of the kernel's `svc/` leaf) when the cell has a tree; on stop the supervisor kills that leaf (`cgroup.kill`, so guest descendants are included) and removes it, so a guest child cannot outlive the Run and leaves do not accumulate. Memory/pids limits arrive with the delegated launch.

**Allowlist (kernel-side).** World and per-node scratch leaf writable; merged-usr directories read+execute; a narrow `/etc` file list plus `/etc/ssl/certs`, `/etc/ssl/openssl.cnf` and `/proc` read; five device files granted individually; `/tmp`, `/home`, `/var`, the project checkout and `<home>` itself never granted. The sandbox owns `HOME=<world>`, `TMPDIR=<scratch>`, `HISTFILE=/dev/null`. A functional probe runs at first execute (not at startup), in the short-lived launcher process: write/read-back/remove in each writable dir, an exact-`EACCES` read of a denied path, the paired `/proc/<ppid>` check (stat readable, environ denied). Any failure exits **125** with one `es-landlock:` stderr line and never runs the command; `spawn-failed` is settled only under the documented conjunction — sandbox active, no start marker, exit 125, retained spawn-capture bytes carrying that signature (a child can forge stderr; an unknown exit code deliberately fails it). `sandboxStatus()` reports honestly — `{mode:'off'}` for `--no-sandbox` (the loud opt-out), `null` before a probe, `{mode:'landlock', abi, enforcement}` with `full` = ABI ≥ 6, `partial` = ABI 3–5. The mode is recorded for the host's lifetime in the owner record (`host.json`, an optional `sandbox` key — pre-mode records stay valid) and on the `host/boot` line, and `status` surfaces it while a host holds the record; it is deliberately not a journal fact (the frontier is exchange-only and the journaled config cannot grow fields). ABI floor 3 (`TRUNCATE`): below it, `open(O_TRUNC)` bypasses write mediation and the guarantee is void. `SCOPE_SIGNAL` and `SCOPE_ABSTRACT_UNIX_SOCKET` are enabled at ABI ≥ 6.

**Scope honesty (current).** The guarantee is scoped to filesystem *content*: `providers.json`, the frontier journal, local logs and host files outside the read set are unreadable and unwritable from the shell. It is not a claim about ambient authority: shell egress is open by design (no network rights handled at all), pathname UNIX sockets are unmediated at ABI 8 (no such right before `RESOLVE_UNIX`, ABI 9; UDP only in master, ABI 10; no raw-socket right at any ABI), and the io_uring `URING_CMD` surface currently bypasses `IOCTL_DEV` (documented LKML report, fix pending upstream). Metadata mutations, existence checks and `chdir` succeed without content access; `/proc/<pid>/{cmdline,stat,status}` stay world-readable under the default `hidepid=0` mount, so no secret may ever sit in argv (the provider key travels in memory only). `no_new_privs` kills setuid/file-capability elevation; `ping_group_range` defaults to `1 0` (denied). `/sys` is not granted (lscpu/lsblk need sysfs) and `/dev/ptmx` is not granted (no new PTYs). Cell cgroups exist: the kernel builds the per-cell tree at boot and moves itself into `svc/`; the launcher joins each shell/Run leaf before restricting itself (the attach write happens pre-restriction, because cgroupfs is never granted — a confined shell with cgroupfs write access could move itself out of its leaf). `cgroup.freeze`/`cgroup.kill` work unprivileged; memory/pids limits (`memory.max`/`pids.max`) are written only under the delegated service launch, where the cell root's controllers are enabled (a direct launch keeps the tree and freeze/kill without them). The attach is degrading, never fail-closed: a host without cgroup v2 runs Landlock-only with one bounded diagnostic. A non-root kernel uid is assumed (DAC underpins the `/etc/shadow` class Landlock does not cover). **The delegated launch** (`scripts/start-service.mjs`) runs the kernel as the MainPID of a transient systemd user service in a delegated slice (`--property=Delegate=yes --property=KillMode=control-group --property=TimeoutStopSec=45`, `--collect` so a crashed name is reusable, `--expand-environment=no` so argv is literal): systemd then reaps the whole cell cgroup when the kernel dies — the reaper, with no custom binary (measured: a setsid'd sleeper inside a node leaf is gone within the poll window after SIGKILL of the MainPID). Under that shape the cell root's controllers are enabled and the `svc/`, node and Run leaves carry `memory.max`/`pids.max` (4 GiB/1,024 each; the cell root itself is uncapped); a host where the enable fails (a direct `npm start`, a non-delegated scope) still builds the cell tree and keeps freeze/kill working; only the delegated `memory.max`/`pids.max` limits are absent, and the boot line says so. `host/boot` records `launch` and `reap` (`service`/`direct`), `limits` (`available`/`unavailable`), `fence` (`available`/`unavailable` — the host-lifetime commit-fence availability, also carried in `host.json` and surfaced by `status`; a fenced host's lines stay byte-identical), and `world` (`degraded`/`healthy` — the durable `<home>/world-state.json` sidecar replayed at composition, so a boot-reconcile refusal is visible; a missing file reads healthy and is never fabricated), and the kernel's stderr goes to the user journal (`journalctl --user -u es-<hash> --output=cat`). `loginctl enable-linger $USER` is required if a cell must survive logout. With the kill switch absent, a stop is cooperative.

**The commit fence.** Every commit's critical section — the nested-repository walk → `add` → `write-tree` → `commit-tree` → `update-ref` — runs with this cell's confined children frozen: every `node-*` leaf — the committing node's own leaf created first if absent, so an idle or boot-reconcile commit freezes an empty leaf, a tested fact — plus every existing `run-*` leaf, enumerated read-only. Under a multi-node host the worktree is shared, so the critical section is the cell's, not the committer's: another node's shell must not write while any node commits. The seam is one host-built `FencePort`: one `acquire`/`release` wraps ONE `commitWorld` attempt, outside the commit queue and the internal git retries (a retry does not thaw), `release` runs in a `finally` before the closer and before shutdown, and a stop never aborts the commit. An empty cgroup's `frozen 1` is a tested fact; a leaf that vanishes between enumeration and the freeze write is gone (the port re-enumerates and retries once), a leaf that vanishes while waiting is dropped from the wait rather than held to the deadline, a `run-*` leaf the first enumeration cannot `readdir`/`lstat` for any reason other than ENOENT/ENOTDIR (EACCES, EIO) is a freeze failure (thaw and typed refusal, never `fenced: true`), a leaf that cannot be statted on the vanish retry is the same freeze failure, and `svc/` is never a target. Each freeze attempt is bounded by 2 s (20 ms poll); a vanished-leaf retry is a second bounded attempt (4 s worst case). `COMMIT_DEADLINE` is not a mechanism: the per-child git deadlines and the walk's own 30 s budget bound completed operations (a single stalled filesystem call is the residual above); no shell or Run deadline is armed across `commitWorld` by construction (their calls are awaited inside the handler, and the driver's one timer seam is the post-refusal retry), so the fence needs no pause.

The two degradation cases have two different carriers. **No fence at boot** (no cgroup v2, a degraded attach, an off cell): commits proceed unfenced — degrade, never die — and the fact is host-lifetime, not per-commit: an optional `fence: 'available' | 'unavailable'` (with a bounded `fenceReason`) on the owner record, `fence` on `host/boot`, and `host.fence` in `status --json` (the human host line prints `fence=unavailable` only when unavailable). It is annotated after the attach and no later successful commit clears it. **A present port that cannot hold the cell** — a freeze failure, a port that reports `unavailable`, or an acquire that throws — is never an unfenced commit: it becomes the typed refusal `freeze-timeout` with a bounded detail, the turn ends `waiting`, the sidecar is degraded and the bounded self-retry runs — and the leaves are thawed before the refusal is recorded. Only the ABSENCE of a port is the unfenced case, and the owner record carries that fact from boot. A SIGKILL between freeze and thaw leaves frozen leaves; `bootHygiene` thaws and then kills every `node-*`/`run-*` leaf under the cell root before the boot, and a leaf that survives the thaw/kill is reported as `host/degraded` `boot-thaw-failed` with its bounded leaf names, never silently booted over; an unreadable cell-root listing is the bounded `boot-hygiene-failed` diagnostic instead of "no leaves" (a boot under a different anchor is not revisited: the old unit's `KillMode=control-group` reaps it — a declared residual). A writer frozen mid-write can leave a torn file in the worktree: the fence prevents mutation *during* staging, not torn content produced before the freeze — the torn-write residual, exhibited by the torn-write harness (a writer frozen between BEGIN and END commits its prefix); the fence-off control exhibits the mutation the fence stops.

**The world doctor.** Composition runs one diagnostic pass (including one bounded, proven-safe repair) on the opened world between `WorldRepo.open` and the frontier open, before `NodeDriver.open` and its boot-reconcile commit; `WorldRepo.open` holds no closeable resource, every helper child is awaited, and a doctor failure is a bounded host diagnostic, never a refused boot. It probes the world lock non-blocking (`flock -n <world.lock>`): a held lock is live and is reported, never removed; with a free lock, an `index.lock` older than `INDEX_STALE_MS` (5 min; above the fixed part of one commit attempt and above every child's deadline, the property the age rule needs — a live child holds `index.lock` only for its own bound of at most 30 s) is removed under the same flock in exec form (`flock -n <world.lock> rm -f -- <index.lock>`), and a lock it cannot prove stale is left. A missing `flock` records `unverifiable` and removes nothing; human git, outside our flock, is the declared residual covered by the age rule. The index is validated STRUCTURALLY only: readable, no unmerged stages, every named blob object present. The structural checks never compare to HEAD and divergence is never repaired; the dirty tree is reported as bounded counts from the ordinary worktree/index listings (a count, never a payload), a difference being a fact rather than corruption. Tracked unreadable paths are reported — there is no per-path skip in `add --all`, so the commit itself either succeeds or refuses typed; the lstat sweep is bounded by the doctor's scan cap and a cut sweep sets `dirty.truncated`. Untracked, unstageable paths (unreadable, foreign-owned, `EPERM`, or special) are quarantined by move into `<home>/.es/quarantine/`, bounded at 1,000 files / 256 MiB and gated on a free-space proof (`statfs`): the disk must have room for the bounded move (up to 256 MiB and 1,000 entries), and a probe that fails or reports less room moves nothing; the 20 GiB storage floor is reported as `freeSpace.state` (a low disk is a fact, not a refusal to rename within the same filesystem). The lock probe is a check, not a held lock: a held lock skips the move, but a peer that acquires the flock after the probe can interleave its own commit with the move — the declared residual (the targeted files are the unstageable ones git cannot add). The named-turn recovery commit is untouched. The report — lock state, index structural state, dirty counts, the bounded tracked-unreadable list, quarantine counts with bounded relative names, and the free-space state — is passed to `NodeDriver.open` and written as the ignorable local event `world/doctor` after `node/boot`; the doctor itself validates the final report with `parseDoctorReport` (a report its own fold would reject is a programming error here, reported as `world/doctor-failed`, never a poisoned journal) and never opens a writer, the driver validates the payload again before writing (an invalid one is a named `InvalidDoctorReportError` on the error channel, with NO event), the fold validates the payload and renders nothing (replay-identical, and an older reader skips it), and no absolute path enters the report.

**Persistent PTY.** One `node-pty` session per node behind a narrow `TerminalRuntime` port (`run`/`dispose`, optional `sandboxStatus`). Nonce markers on a single physical line; typed statuses (`completed` | `stdin_read` | `timeout` | `session_exit` | `cancelled` | `spawn-failed`); one active write per node; bounded per-command capture, no scrollback; a timeout kills and respawns the session. A PTY merges stdout and stderr into one stream; the model-facing render is sanitized, the local artifact keeps the verbatim bounded capture. The stdin-read wait is the Linux x86-64 `/proc` proof (`CONFIG_HAVE_ARCH_TRACEHOOK`; the syscall table is x86-64's), bound to the pts path frozen at spawn — on other architectures the exact-match-only design degrades to a timeout, never a false positive. The PTY does not survive a kernel restart (a new process cannot inherit a master it does not own); shell state is ephemeral, what matters is externalized. Three deliberate divergences from dsh's `tool-bash-persistent`: a stdin-wedged session is reset before the next command, a capture overflow never kills the command, completion wins over a same-tick abort. The interactive `write` verb is **specified, not implemented**.

## Credential store and broker

A node may need third-party credentials; no secret may ever enter the world. The kernel-side store (`<home>/providers.json`, plaintext at rest, unreadable and unwritable from the confined shell; schema in [architecture.md](architecture.md)) is implemented. The full broker is **specified, not implemented**: the agent's environment carries an endpoint-bound *placeholder*, never the secret; the broker substitutes the real credential on the wire only for the bound endpoint, refusing and recording a mismatch without leaking secret, placeholder or variable name — the pattern validated by [NVIDIA OpenShell](https://github.com/NVIDIA/OpenShell) (Apache 2.0: gateway-held providers, endpoint-bound placeholders, `credential_endpoint_mismatch` refusal; 1Password × OpenShell adds time-bound TTL custody). Plain environment injection is **rejected**: the real value would transit the agent's process, exfiltratable and invisible to the frontier. Every authenticated request is a frontier exchange; which providers a node may use is a capability attenuated at the gate.

## Kill switch and budget

**Specified, not implemented.** The kill switch is a bounded, escalating shutdown — first signal: graceful disposal of the tree with a 5-second backstop (a safety invariant, not a tunable); re-signal: immediate exit (the dsh `process-shutdown` pattern). The budget is a hard limit on the API key, set upstream, invisible to the agents; cost is a projection of complete frontier bodies computed on the human side only. The explicit `unhandledRejection` handler is implemented: it records `host/unhandled-rejection`, requests the graceful stop and exits 1, never Node's default (`--unhandled-rejections=throw`) crash. Only the escalating kill switch and the upstream budget are absent. Until the switch exists, a stop is cooperative.

## Model-selection criteria

The design is model-agnostic. A candidate must: (1) exist behind an OpenAI-compatible endpoint; (2) carry an acceptable license — DeepSeek V4.1 Flash ships open weights under MIT; GLM-5.3, GLM-5.3-Flash and Kimi K2.7 Code exist as verified vendor offerings; (3) report cache usage (Anthropic: `cache_control` breakpoints, max 4, 20-block lookback window; DeepSeek: `prompt_cache_hit/miss_tokens`; OpenAI-compat: `prompt_tokens_details.cached_tokens`; Z.ai: automatic caching on its OpenAI-compat endpoint, `cache_control` honored on its Anthropic-compat endpoint). The first cost lever is the cache-hit rate, hence the byte-stable prefix. Long-session capability claims (Kimi K2.7 Code: 12h+ sessions, 4000+ tool calls, ~30% fewer reasoning tokens) are vendor-reported, not independently evaluated. Prices, index scores and routing tables are volatile and deliberately absent.

## Skills (target design)

The skills system is **specified, not implemented**: specified `src/skills/<name>.ts` modules behind a specified `src/cli/skills.ts` command, no new dependencies. Eight skills, each a repo-verification or maintenance routine invoked by name: `verify-tests`, `verify-secrets`, `verify-sandbox`, `verify-frontier`, `update-docs`, `review-code`, `build-hermetic`, `format-code`. No skill exists in the tree; none may be assumed by docs or tooling.

## Patterns adopted from prior art
